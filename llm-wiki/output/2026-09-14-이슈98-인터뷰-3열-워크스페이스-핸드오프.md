## 1. 디자인과 다른 이슈 Constraint가 충돌할 때의 판단 기준

#97은 1차 구현에서 master-detail *배치*만 디자인대로 바꾸고 콘텐츠는 기존 UI를 그대로
남겼다가, 사용자가 실제 화면을 보고 "참고 Figma와 전혀 다르다"고 지적해 다시 작업했습니다.
이 과정에서 정한 기준을 그대로 옮깁니다.

- 디자인에 없고 순수 UI 취향이었던 요소(예: 출처 배지, 지표 묶음)는 디자인대로 뺍니다.
- 다른 이슈가 정한 Constraint는 디자인 선호보다 우선합니다. 이슈 #98의 Constraints에 있는
  "확인 가능 여부 안내와 patch 절단 안내를 제거하지 않습니다"가 정확히 이 종류입니다.
  디자인(`CodePanel`)에 이 안내들의 자리가 없다고 해서 빼면 안 되고, 화면 어딘가에는
  반드시 남아야 합니다.
- 이 둘이 부딪히면 먼저 사용자에게 설명하고 승인을 받은 뒤 반영하세요. #97에서는 "화면에서
  완전히 삭제" 대신 "시각적으로는 숨기고 스크린리더·`aria-describedby` 연결은 유지"하는
  절충안으로 두 번 해결했습니다(2절 참고). #98에서 디자인에 안내 문구가 들어갈 자리가
  마땅치 않으면 같은 절충안을 검토할 만합니다.

## 2. 확인 가능·불가 안내를 시각적으로만 숨기는 패턴

`src/features/experience-candidates/experience-candidate-detail.module.css`의
`.evidenceNotice, .verifiedNotice, .aiSelectionNotice` 규칙이 그 구현입니다.

```css
.evidenceNotice, .verifiedNotice, .aiSelectionNotice {
  position: absolute; width: 1px; height: 1px; margin: -1px; padding: 0;
  overflow: hidden; clip: rect(0, 0, 0, 0); white-space: nowrap; border: 0;
}
```

버튼의 `aria-describedby`가 가리키는 문단을 DOM에서 지우면 스크린리더가 그 설명을 듣지
못합니다(이슈 #47 PR #52 1차 리뷰의 P1이 같은 문제였습니다). 화면에서 안 보이게만 하고
DOM·`aria-describedby` 연결은 남기면 접근성과 디자인 요구를 동시에 만족합니다. `patch
절단 안내`처럼 `aria-describedby` 연결이 없는 안내는 이 패턴을 쓸 필요 없이 디자인에
맞는 자리를 그냥 새로 만들면 됩니다.

## 3. `interview-evidence-panel.tsx`에 미번역 상태로 남아 있는 것

이 파일은 `evidence-verifiability.ts`의 공유 상수(`VERIFIABILITY_LABEL` 등)를 그대로
가져다 쓰고 있어 그 상수들은 이미 영어입니다. 하지만 이 파일 자체가 그리는 문구 하나는
아직 한국어입니다.

```
src/features/interview/interview-evidence-panel.tsx:186
<h4 id="interview-unverifiable-heading">Repository로 확인할 수 없는 항목</h4>
```

#97이 이 파일 자체는 손대지 않기로 판단해서(공유 상수만 옮기는 것으로 범위를 좁힘) 그대로
뒀습니다. #98은 이 컴포넌트를 `CodePanel`로 통째로 재구성하므로, 이 헤딩을 디자인 개편
공통 결정("화면 문구는 디자인대로 영어")에 맞춰 영어로 옮길지 이번에 정해야 합니다. 참고로
같은 목록(`REPOSITORY_UNVERIFIABLE_ITEMS`)을 쓰던 경험 후보 상세 화면 쪽 절은 #97에서
사용자 요청으로 화면에서 아예 뺐습니다(4절 참고). 두 화면이 지금 이 목록을 다르게
다루고 있다는 점을 인지하고 있어야 합니다 — 인터뷰 화면 쪽은 이슈 #98 Constraint가
지우지 말라고 명시하고 있으니 그대로 유지하되, 표시 문구만 영어로 바꿀지 여부를 판단하면
됩니다.

## 4. 경험 후보 화면에서 뺀 것과의 비대칭

#97 작업 중 사용자가 브라우저에서 직접 화면을 확인하며 다음을 요청해 뺐습니다.

- "Repository evidence" 섹션의 확인 가능·불가 설명 문단 중 `aria-describedby` 연결이
  없는 것(스키마 공백 안내 일부)은 완전히 삭제.
- 상세 화면 하단의 "What can't be confirmed from the Repository" 고정 목록 섹션 전체를
  삭제(태그 자체(`Verified`/`AI-selected`)는 유지).

이건 경험 후보 화면(#97)에 한정된 결정이고, 인터뷰 화면(#98)에는 적용된 적이 없습니다.
#98에서 "다른 화면도 이렇게 정리했으니 여기도 빼자"고 유추하지 마세요. 이슈 #98
Constraints가 명시적으로 막고 있습니다.

## 5. CSS 관례

- 색·라운드·타이포그래피는 전부 `globals.css` 토큰만 씁니다(`--color-*`,
  `--font-mono`, `--label-size-*`, `--radius`). 새 하드코딩 hex를 넣기 전에 토큰에
  대응 값이 있는지 먼저 확인하세요.
- 시각적으로 숨기는 유틸(2절의 CSS)은 이 코드베이스에서 CSS Module 파일마다 필요한 곳에
  그대로 복제해서 씁니다. `repository-analysis.module.css`의 `.visuallyHidden`과
  `experience-candidate-detail.module.css`의 것이 완전히 같은 선언인데도 공유 파일로
  뽑지 않았습니다. 파일 간 셀렉터 공유보다 각 모듈이 자기 완결적인 것을 우선한 판단이니,
  `CodePanel`의 CSS Module에도 필요하면 그대로 복제하면 됩니다.
