# Stage A 개별 예산 선별 설계 논의

## 이어받은 근거

[이슈 #101 측정](2026-09-11-이슈101-프롬프트교체-편향측정-session-log.md)과 사용자가 제공한 선별 로직 설명을 바탕으로 논의했습니다. 이번 세션에서는 새로운 모델 호출이나 성능 측정을 수행하지 않았습니다.

## 논의 순서

1. 사용자가 단일 커밋 입력 구현과 혼합 저장소 테스트를 마쳤으며, Algorithm의 0점 434개가 Stage A 이전에 제외된다고 설명했습니다.
2. 점수식보다 동점 그룹 전체 제외 규칙이 직접 원인이라고 판단했습니다. 1점 항목 하나가 먼저 선택되면 나머지 동점 그룹을 분할하지 못하는 구조가 남은 입력 예산을 사용하지 못하게 합니다.
3. 점수순 정렬과 동점 입력 순서를 유지하면서 각 WorkUnit에 개수·바이트 예산을 적용하는 방식을 제안했습니다. 한 항목이 들어가지 않아도 뒤 항목은 계속 확인하고, 0점도 입력 기회를 갖도록 합니다.
4. 단일 커밋 가산점은 큰 동점 그룹을 해소하지 못하고, 새로운 규모 신호나 종류별 할당은 실측 근거가 부족하므로 이번 변경에서 제외했습니다. 혼합 저장소의 점수 편향은 후속 측정으로 구분했습니다.
5. 사용자가 구현 담당 에이전트에게 전달할 문서를 요청했습니다. 현재 선별 구현, 화면의 `thresholdScore` 참조와 기존 실측 기록을 확인하고 [구현 인계 문서](../output/2026-09-11-Stage-A-개별-예산-선별-구현-인계.md)를 작성했습니다.

## 상태

제품 코드는 변경하지 않았습니다. Algorithm의 200개 선택·235개 제외는 바이트 예산이 충분할 때의 기대 결과이며 신규 측정값이 아닙니다. 구현 담당 에이전트가 실제 바이트, 회귀 테스트 및 호출부 연결을 검증해야 합니다.
