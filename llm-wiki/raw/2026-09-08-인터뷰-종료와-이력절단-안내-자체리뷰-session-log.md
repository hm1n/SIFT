## 1. 반영한 것

### 도달 증명이 없던 방어 코드

`submitAnswer`의 `isEndedRef` 가드가 실제로 도달하는지 확인했습니다. 종료와 제출이 서로 다른 사용자 이벤트라면 그 사이에 렌더와 effect가 끼므로 `canSubmitRef`가 이미 거짓이고, 그렇다면 `isEndedRef` 가드는 도달하지 않는 코드가 됩니다.

도달 경로는 한 이벤트 핸들러가 종료와 제출을 잇따라 부르는 경우입니다. 그 경로에서 가드가 없으면 답변이 종료한 대화에 들어갑니다. 회귀 테스트를 같은 `act` 안에서 `endInterview()`와 `submitAnswer()`를 부르는 모양으로 넣어 그 자리를 고정했습니다.

`retry`와 `start`의 가드는 이미 테스트가 있습니다. `retry`는 요청 전에 마지막 질문을 지우므로 `start`의 가드로 대신할 수 없다는 점도 그대로 둡니다.

### 같은 모양의 버튼 클래스 두 개

`.endButton`과 `.endCancelButton`이 `width` 하나만 다르고 나머지가 같았습니다. 하나로 합치고 확인 대화의 취소 버튼도 같은 클래스를 쓰게 했습니다. CSS 두 줄이 줄었습니다.

## 2. 테스트 안정화

절단 안내 테스트를 넣은 뒤 기존 스크롤 테스트("위로 올려 읽는 중에 새 질문이 도착하면 자리를 빼앗지 않고 안내만 한다")가 간헐적으로 실패했습니다. 세 번 돌리면 한 번 실패하는 빈도였습니다.

`develop`의 같은 파일을 네 번 돌려 전부 통과하는 것을 확인했으므로, 이번에 늘어난 테스트가 실패를 드러낸 것입니다. 실패는 새 메시지 안내 버튼을 찾지 못하는 모양이었습니다. 청크 반영과 안내 표시가 서로 다른 렌더에서 일어나는데 그 테스트가 동기 조회로 잡고 있었습니다.

두 가지를 고쳤습니다. 절단 안내 테스트가 마지막 스트림을 완결시키지 않고 끝나 열린 스트림을 남기던 것을 완결시키도록 했고, 스크롤 테스트의 동기 조회를 `findByRole`로 바꿨습니다. 전자만으로는 재현이 남았고 후자까지 넣은 뒤 화면 테스트 파일 5회, 전체 스위트 3회가 모두 통과했습니다.

## 3. 반영하지 않고 남긴 것

확인 대화에서 "계속하기"를 누르면 확인 대화가 사라지고 초점이 문서 본문으로 빠집니다. 확인 대화를 열 때는 `autoFocus`로 확인 버튼에 초점을 옮기지만, 닫을 때 종료 버튼으로 되돌리려면 그 버튼이 다시 마운트된 뒤에 초점을 옮겨야 하므로 ref와 effect가 필요합니다.

기능 오동작이 아니고 키보드로 계속 진행할 수 있으므로 P3으로 보고 `wiki/2026-09-08-꼬리질문-요청계약-후속-backlog.md` 8번으로 분리했습니다.
