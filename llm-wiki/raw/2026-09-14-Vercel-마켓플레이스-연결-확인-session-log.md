# Vercel 마켓플레이스 연결 확인 세션 로그

`2026-09-14-Neon-접속환경-설정-session-log.md`가 남긴 "Vercel 마켓플레이스 연결은 아직 하지 않았습니다"를 이어받습니다.

## 연결 전에 짚은 것

사용자가 Vercel 마켓플레이스가 무엇인지 물었습니다. 설명하면서 이슈 원안과 지금 상태가 어긋난 지점을 발견했습니다. 이슈는 Neon 프로젝트가 없는 상태를 전제하고 마켓플레이스로 새로 만드는 흐름을 적었는데, 이 세션에서 이미 `neon link`로 프로젝트를 만들어 표까지 넣은 뒤였습니다. 그대로 새로 설치하면 별개의 Neon 프로젝트가 하나 더 생겨 표를 만든 쪽과 Vercel이 가리키는 쪽이 갈릴 수 있었습니다.

선택지를 셋으로 정리해 드렸습니다. Vercel 프로젝트에 환경변수를 손으로 넣기, 마켓플레이스에서 기존 계정을 연결하기, 마켓플레이스로 새로 만들고 지금 것을 버리기입니다. 사용자가 둘째를 택해 직접 연결했습니다.

## 연결 후 확인한 것

- `neon projects list`가 `steep-feather-35162878` 하나만 보여 줍니다. 새 프로젝트가 생기지 않았습니다.
- 브랜치가 하나 늘었습니다. `vercel-dev`(`br-billowing-glade-ae3g0epp`)가 06:04:22Z에 생겼습니다. Vercel이 Development 환경용으로 만드는 브랜치입니다.
- `neon inspect db table-sizes`를 `production`과 `vercel-dev` 양쪽에 돌려 표 두 개가 모두 있는 것을 확인했습니다. 스키마를 적용한 뒤에 브랜치가 갈라져서 그대로 복사됐습니다.
- 데이터베이스는 `neondb` 하나, 역할은 `neondb_owner` 하나 그대로입니다. 연결이 새 역할을 만들지 않았습니다.

Vercel 프로젝트에 주입된 환경변수 이름은 확인하지 못했습니다. `vercel` CLI가 설치돼 있지 않고 이 워크트리에 `.vercel`도 없습니다.

## 첫 질의가 연결 단계에서 끊기는 것

오늘 `npm run db:schema`를 네 번 돌렸는데, 한동안 쉬었다가 처음 부른 두 번이 모두 같은 오류로 죽었습니다.

```
ConnectTimeoutError: Connect Timeout Error
(attempted address: api.c-2.us-east-2.aws.neon.tech:443, timeout: 10000ms)
```

응답이 느린 것이 아니라 TCP와 TLS 연결이 10초 안에 맺어지지 않는 단계입니다. 두 번 모두 곧바로 다시 돌리니 정상으로 끝났습니다.

원인을 단정하지 않았습니다. Neon이 5분 유휴 후 컴퓨트를 내렸다가 다음 연결에서 깨어나는 동작과 시점이 맞지만, 그것을 확인하려고 유휴 시간을 바꿔 가며 재보지는 않았습니다. 중간에 같은 호스트로 직접 `fetch`를 했을 때는 1077ms에 400이 돌아와 호스트 자체는 살아 있었는데, 그 호출이 컴퓨트를 깨우는 경로인지도 확인하지 않았습니다.

기능 정의서가 이 상황을 이미 적어 두고 있습니다. "Neon 컴퓨트가 잠들어 있었다면 첫 질의가 깨어나기를 기다립니다."

대응은 이번 이슈에서 하지 않았습니다. 실제 저장 호출이 생기는 #115에서 재현 조건을 재고 재시도를 넣을지 타임아웃을 늘릴지 정하는 것이 맞다고 봤습니다. 지금 넣으면 원인을 모르는 채로 상수를 고르게 됩니다.

## 남은 어긋남 하나

로컬 `.env.local`은 `neon link`가 써 준 값이라 `production` 브랜치를 가리킵니다. Vercel의 Development 환경은 `vercel-dev`를 가리킵니다. 로컬에서 개발하면 프로덕션 브랜치에 쓰게 되므로, 로컬을 `vercel-dev`로 옮길지는 정하지 않았습니다.
