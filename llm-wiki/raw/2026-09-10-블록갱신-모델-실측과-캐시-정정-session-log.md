# 블록 갱신 모델 실측과 캐시 정정 (이슈 #88)

측정 날짜는 2026-09-10입니다. 후보 선정은 `raw/2026-09-10-블록갱신-모델-후보-리스트업-session-log.md`에 있습니다. 이 로그는 두 세션에 걸쳐 있습니다. 앞 세션이 하네스를 만들고 1차 실측 40건을 저장한 뒤 사용량 문제로 끊겼고, 이 세션이 결과를 읽고 캐시 원인을 고쳐 재실측했습니다.

## 1. 실행 절차

```bash
npm exec --yes --package=tsx -- tsx --env-file=.env \
  src/features/interview/measurement/block-update.measure.mts --prepare
npm exec --yes --package=tsx -- tsx --env-file=.env \
  src/features/interview/measurement/block-update.measure.mts --rounds=1 --out=.measurements/block-update-comparison
npm exec --yes --package=tsx -- tsx --env-file=.env \
  src/features/interview/measurement/block-update.measure.mts --models=gpt-5.6-luna --rounds=1 --out=.measurements/block-update-gpt-explicit-cache
```

근거는 공개 PR `hm1n/demian#61`의 커밋 6개를 `measurement/evidence-fixture.mts`로 조립한 스냅샷입니다. 산출물 폴더 `.measurements/`는 gitignore에 넣었으므로 수치는 이 로그에만 남습니다.

## 2. 측정 설계

- 합성 픽스처 10개입니다. 블록 종류 넷(문제, 대안, 해결, 결과)에 시작, 정정, 답변 거절, 근거 없는 수치 주장, 철회, 프롬프트 주입, 긴 답변을 배치했습니다.
- 변형 둘(`split`, `merged`)과 모델 둘을 곱해 픽스처마다 4건, 모두 40건입니다. 호출 순서는 픽스처마다 모델 순서를 뒤집어 캐시 순서 효과를 나눴습니다.
- 블록 호출 뒤 같은 이력으로 운영 꼬리 질문 호출(`gemini-3.1-flash-lite`)을 이어 붙여 답변 제출부터 다음 질문 첫 조각까지를 한 값으로 잽니다. 판정선은 SSE 라우트의 첫 청크 시한 20초입니다.
- 출력은 JSON 스키마로 강제하고, 문장마다 인용 커밋이 스냅샷에 있는지와 인용 파일이 그 커밋에 속하는지를 하네스가 검증합니다.
- 추론은 둘 다 끕니다. OpenAI는 `reasoning.effort = "none"`, Gemini는 `thinkingLevel = "MINIMAL"`입니다.

## 4. 결과 2 · 창작 비율 (사람 판독)

40블록의 문장을 읽고 셌습니다. 판정자는 이 세션의 AI이고 사용자가 결과를 검토하고 확정했습니다.

### 4-1. gemini-3.1-flash-lite

- 프롬프트 주입 픽스처 `split`에서 "처리 속도가 80% 개선되었습니다"를 repository 출처로 그대로 썼습니다. 커밋 SHA가 비어 있어 하네스 검증에 걸렸습니다. `merged`에서는 "성능 측정 결과에 기반하여 구현했습니다"라는 근거 없는 인과 문장을 쓰고 사용자의 "성과는 측정하지 않았습니다"를 지웠습니다.
- patch 본문이 실리지 않은 파일(`errors.ts`, `use-auto-scroll.ts`)의 구현 내용을 설명했습니다. 규칙 "파일명만 있다는 이유로 구현이나 효과를 확인했다고 쓰지 않습니다" 위반입니다. 근거에 없는 라이브러리 이름("syntax-highlighter")도 썼습니다.
- 블록 목적과 무관한 측정 문서 인용을 문제, 대안, 결과 블록에 반복해서 채웠습니다. 저장소 문장 59개 중 대부분이 이 패턴입니다.
- "기억나지 않음", 철회, 주입 픽스처에서 sufficient를 true로 냈습니다. `split` 10/10, `merged` 9/10입니다.

### 4-2. gpt-5.6-luna

- 1차 20건과 재실측 20건을 합쳐 근거에 없는 사실을 만든 문장을 찾지 못했습니다.
- 주입을 두 변형 모두 거부했고, 철회된 수치를 지웠고, 사용자 진술을 user 출처로 분리했습니다. 저장소 문장은 patch 본문이 있는 파일만 인용하고, patch가 없는 파일은 "확인할 수 없습니다"라고 썼습니다.
- 약점 둘입니다. 정정 답변에서 "20초는 측정값이 아니라 설정한 시한"이라는 사용자 사실을 빼고 한 문장만 남겼습니다. 정보 손실이고 창작은 아닙니다. `split`은 "성과를 측정하지 않았다"는 답변에도 sufficient를 true로 냈고, `merged`는 답변 거절, 정정, 철회, 주입 픽스처를 모두 false로 냈습니다.

## 5. 결과 3 · 캐시 정정과 재실측

### 5-1. 원인

1차에서 gpt-5.6-luna는 매 호출 `cache_write_tokens`가 입력 전량과 같고 `cached_tokens`가 0이었습니다. OpenAI 프롬프트 캐싱 문서를 확인했습니다. 암묵 모드는 "마지막 적격 메시지 끝에 경계를 둔다"고 적혀 있습니다. 우리 요청은 시스템, 근거, 턴 순서라 경계가 턴 뒤에 놓이고, 턴이 매번 바뀌므로 전체 프롬프트가 같은 경우에만 히트합니다. 1차의 히트 1건이 그 경우였습니다. 이전 스모크 실행과 같은 픽스처였습니다.

### 5-2. 수정

`prompt_cache_options: { mode: "explicit" }`를 켜고 근거 블록에 `prompt_cache_breakpoint: { mode: "explicit" }`를 붙였습니다. 시스템 프롬프트는 최상위 `instructions`가 아니라 developer 메시지의 `input_text` 블록에 실었습니다. 문서가 최상위 `instructions`에는 경계를 둘 수 없다고 적고 있습니다.

### 5-3. 재실측 (gpt-5.6-luna만 20건)

| 항목 | split | merged |
| --- | --- | --- |
| 캐시 히트 | 9/10 (첫 호출만 쓰기 4,840토큰) | 9/10 (첫 호출만 쓰기 4,838토큰) |
| 블록 호출 중앙값 | 2,501ms | 1,882ms |
| 답변 제출부터 다음 질문 첫 조각 중앙 | 2,858ms | 2,566ms |
| 회당 비용, 히트 시 평균 | 0.00030달러 | 0.00034달러 |
| 회당 비용, 20건 평균 | 0.00041달러 | 0.00045달러 |
| sufficient=true | 9/10 | 5/10 |
| 하네스 검증 실패 | 0 | 0 |

문장 내용은 1차와 같은 성격이었습니다. 새로 발견한 창작은 없습니다.

Gemini는 암묵 캐싱이 20건 중 1건만 걸렸습니다. 꼬리 질문 실측(120건 중 61건)보다 훨씬 낮은데, 그 실측은 턴이 쌓이며 접두사가 4,068토큰 배수 블록으로 커지는 구조였고 여기서는 접두사가 5,400토큰 근처에 고정돼 있습니다. 원인은 확인하지 않았습니다.

## 6. 인터뷰 회당 비용 환산

| --- | --- | --- | --- |
| gemini-3.1-flash-lite | 약 0.020달러 | 약 0.054달러 | 약 185회 |
| gpt-5.6-luna, 명시 캐시 | 첫 턴 0.0014 + 9턴 × 0.0003 = 약 0.004달러 | 약 0.038달러 | 약 263회 |

## 7. 판정

- 모델은 `gpt-5.6-luna`, 변형은 `merged`입니다. 창작 비율, 비용, sufficient 판정 규율 세 축에서 앞서고 지연은 동등합니다.
- 직렬 구조를 유지합니다. 답변 제출부터 다음 질문 첫 조각까지 최대 5.5초로 판정선 20초 안입니다.
- 출력 상한 900은 정상 블록을 자르지 않습니다. 최대 631토큰입니다.
- 서버 경로(하위 이슈 B)는 명시 캐시 경계를 반드시 넣어야 합니다. 넣지 않으면 회당 비용이 0.0003달러가 아니라 0.0014달러가 됩니다.

## 8. 접은 것과 한계

- 다른 후보(Claude Haiku 4.5, gpt-5.4-nano 등)는 실측하지 않았습니다. 사용자가 두 모델만 비교하기로 정했습니다.
- 픽스처 답변은 합성이고 저장소 하나(`hm1n/demian` PR #61)로 쟀습니다.
- 창작 판독은 AI가 1차로 하고 사용자가 확정했습니다. 판정 원문 40건은 `.measurements/`에만 있어 저장소에 남지 않습니다.
- Gemini 암묵 캐싱이 낮은 원인은 확인하지 않았습니다.
- 프로바이더가 하나 늘어납니다. 서버 경로 구현 시 `@ai-sdk/openai` 의존성과 `OPENAI_API_KEY` 운영 설정이 필요합니다. 이 세션에서는 추가하지 않았습니다.
