인라인 코멘트 두 건입니다. 리뷰 도구가 붙인 등급은 각각 P1과 P2였습니다.

2. `interview-stream-view.tsx:54` (P2) — `history_too_large` 안내는 다시 시도해도 같은 결과라고 말하는데 다시 시도 버튼이 남아 있습니다.

## 2. 묶음과 등급 판정

### 묶음 A: 대화가 사라지는 경로에 확인이 없습니다

프로젝트 기준으로도 P1입니다. 이슈 #78의 Why가 "후보 목록으로 돌아가는 버튼이 사실상의 종료인데, 그것이 종료라는 표시가 없고 대화가 사라진다는 안내도 없습니다"라고 적고 있고, Goal이 "끝내면 대화가 사라진다는 것을 끝내기 전에 압니다"입니다. 종료 조작을 새로 만들면서 원래 문제였던 버튼을 그대로 둔 것이므로 핵심 요구사항 위반이고 데이터 손실입니다.

지적되지 않았지만 같은 원인인 것을 함께 봤습니다.

- 뒤로가기는 제출한 답변만이 아니라 작성 중인 답변도 함께 잃습니다. 같은 수정이 덮습니다.
- `InterviewScreen`은 훅 안의 종료 상태와 대화를 모릅니다. 확인을 조건부로 만들려면 훅을 `InterviewStreamView` 밖으로 끌어올려야 하므로, 종료한 뒤에도 한 번 더 묻는 값을 치르고 훅의 자리를 그대로 뒀습니다.
- `beforeunload`는 같은 계열이지만 이번 범위에서 빼기로 이미 정한 항목이라 그대로 뒀습니다(backlog 6번).

### 묶음 B: 풀리지 않는 실패에 다시 시도 조작이 남아 있습니다

프로젝트 기준으로 P2입니다. 기능 오동작이 아니고 잘못된 결과가 사용자에게 가지도 않습니다. 다만 두 예외에 걸려 같은 PR에서 반영했습니다. 이슈 #78의 Why가 "이력을 줄여야 하는 실패에 같은 안내를 주면 사용자는 같은 요청을 반복합니다"라고 적고 있어 문구만 갈라도 버튼이 남으면 같은 문장이 재현되고, 수정 비용은 조건 하나입니다.

지적은 `history_too_large` 하나였지만 같은 오류 박스가 `clearsOnRetry`가 거짓인 아홉 분류 전부에 버튼을 그리고 있었습니다. `unauthorized`, `invalid_json`, `invalid_request`, `body_too_large`, `history_too_large`, `llm_request`, `llm_auth`, `llm_configuration`, `server_error`입니다. 이것은 이번 PR이 만든 결함이 아니라 원래 있던 것이고, 분류마다 조건을 두면 다음 분류가 추가될 때 또 빠지므로 `clearsOnRetry` 하나로 판정하게 했습니다.

기존 테스트 이름이 이미 `같은 근거로는 풀리지 않는 실패에는 재시도를 권하지 않는다`였는데 문구만 검사하고 있었습니다.

## 3. 반영과 커밋

- `c3be6af` 뒤로가기 확인. `interview-screen.tsx`가 확인을 받고, 확인 문구는 종료 확인과 다릅니다. 종료는 입력이 닫힌다고 말하고 뒤로가기는 대화가 사라진다고 말합니다.
- `47020f3` 다시 시도 버튼을 `clearsOnRetry`로 조건부. 상한을 넘은 질문은 예외로 남깁니다. 오류 객체가 없고 다시 시도가 그 질문을 새로 만들어 실제로 상태를 바꿉니다.

## 4. 회귀 테스트

- 묶음 A: `interview-screen.test.tsx`의 기존 `후보 목록으로 돌아갈 수 있다`를 확인 경로로 바꿨습니다. 클릭에 `onBack`이 불리지 않고, 취소하면 그대로이고, 확인하면 한 번 불립니다.
- 묶음 B: `history_too_large` 테스트와 `llm_auth` 테스트에 버튼 부재를 단정했습니다. 기다리면 풀리는 `llm_failure` 테스트에는 버튼이 있어야 한다는 단정을 넣어 조건을 거꾸로 걸면 깨지게 했습니다.

## 5. 고치는 중에 나온 것

`interview-screen.test.tsx`에서 확인 대화를 `getByRole("group")`으로 찾으니 근거 패널의 group과 겹쳐 두 개가 잡혔습니다. 이름으로 좁혔습니다. `InterviewStreamView` 단독 테스트에서는 group이 하나라 겹치지 않습니다.

`experience-selection.test.tsx`의 `목록으로 돌아가 다른 경험을 확정하면 확정 상태가 교체된다`가 뒤로가기를 한 번 눌러 목록으로 가는 것을 전제하고 있어 실패했습니다. 확인 클릭을 더했습니다. 인터뷰 화면 밖에서 같은 라벨을 쓰는 다른 두 자리는 `ExperienceCandidateDetail`의 버튼이라 영향이 없습니다.
