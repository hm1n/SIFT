# 꼬리 질문 요청 계약 PR의 Codex 1차 리뷰 반영 경위

## 1. 받은 지적

Codex가 커밋 `7c6c68db1a`를 보고 3건을 남겼습니다. 셋 다 P2였고 셋 다
`src/features/interview/measurement/followup-question-cost.measure.mts` 한 파일이었습니다.

- GitHub 실패 응답을 분류하지 않고 status만 남긴 채 죽습니다.
- `--max-commits`가 100을 넘으면 첫 페이지만 받고 뒤의 `slice`가 조용히 적게 잽니다.
- `countTokens`의 성공 응답 파싱이 무방비라 raw `SyntaxError`로 끝납니다.

PR 본문의 Review Points에 올린 세 가지는 아무것도 지적받지 않았습니다. 상한 앵커,
`history_too_large` 신설, 프롬프트 바이트 측정 대상 모두 언급이 없었습니다.

## 2. 묶음으로 나눈 기준

지적 3건을 근본 원인 2개로 묶었습니다.

**묶음 A는 실패를 저장소 오류 계약으로 변환하지 않는 것입니다.** 1번과 3번이 여기 들어갑니다. 이
스크립트는 `parseJson`을 이미 제대로 쓰고 있었고, 빠진 곳은 자기 손으로 쓴 `!response.ok` 분기와
raw `fetch`를 쓴 `countTokens`뿐이었습니다. 두 지점이 파일도 대상 API도 다르지만 원인이 같습니다.

**묶음 B는 페이지네이션 미추적입니다.** 2번입니다. 오류 처리가 아니라 조용히 틀린 데이터를 내는
문제라 원인이 다릅니다.

## 3. 지적되지 않은 같은 결함을 찾았습니다

`question-generation.measure.mts:115-122`의 `fetchPullRequestCommitShas`가 지적받은 함수와 같은
함수였습니다. 같은 403 뭉갬, 같은 페이지네이션 누락입니다. 리뷰 도구가 보지 못한 이유는 그 줄이
diff에 없기 때문입니다.

이 단계를 건너뛰었으면 다음 라운드에 다른 줄로 같은 지적이 돌아왔을 것입니다. PR #6이 6라운드
돌았던 원인이 이것이었습니다.

## 4. 등급을 다시 판정한 근거

Codex 등급을 그대로 쓰지 않고 프로젝트 기준으로 다시 봤습니다.

셋 다 P2를 유지했습니다. 측정 스크립트는 개발자가 `npx tsx`로 손수 돌리는 도구이고 서비스
사용자가 닿는 경로가 아닙니다. 실패해도 터미널에 뜨는 메시지가 달라질 뿐입니다.

2번만 따로 봤습니다. 조용히 틀린 측정값을 내고 그 값이 위키와 프로덕션 상수의 근거가 되므로
"항상 실제 측정을 근거로 판단한다"는 작업 원칙이 무너집니다. 다만 이번 실행은
`--pr=61 --pr=56 --pr=67 --turns=10`이었고 `max-commits` 기본값이 6이라 **2026-09-03 측정값은
영향을 받지 않았습니다.** 100을 넘기려면 사용자가 명시적으로 줘야 하므로 발생 조건이 좁아 P2로
두었습니다.

세 건 모두 P2 예외 가운데 **수정 비용이 매우 작은 경우**에 걸려 이번 PR에서 함께 고쳤습니다.
필요한 함수인 `classifyErrorResponse`, `parseJson`, `parseNextLink`가 전부 그 스크립트가 이미
import하는 모듈에 export되어 있었습니다.

## 5. 접은 대안

- **묶음 A를 backlog로 미루는 안.** 미루지 않았습니다. 수정이 몇 줄이라 backlog 항목을 쓰는 비용이
  고치는 비용과 비슷했습니다.
- **페이지네이션 대신 100 초과를 거절하는 안.** 한 줄로 끝나지만 CLI 동작이 바뀝니다. 저장소가
  `parseNextLink`를 이미 갖고 있고 `fetchAllCommits`가 같은 방식을 쓰므로 따라가는 쪽을
  골랐습니다.
- **`countTokens` 실패에 `GitHubFetchError`를 재사용하는 안.** 쓰지 않았습니다. Gemini 호출에
  GitHub 오류 종류를 붙이면 분류가 거짓말이 됩니다. 스크립트 안에 `CountTokensError`를 두고
  `http`, `parse`, `schema`로 갈랐습니다.
- **두 스크립트의 중복 조회 코드를 공용 모듈로 빼는 안.** 이번에 하지 않았습니다. 판단 근거는
  `wiki/2026-09-08-꼬리질문-요청계약-후속-backlog.md` 1번에 있습니다.

## 6. 페이지네이션 구현에서 한 번 되돌린 것

처음에는 `while` 안에서 콜백으로 다음 주소를 대입하는 형태로 썼습니다.

```
shas.push(...(await fetchCommitShaPage(url, pullRequestNumber, (next) => (url = next))));
```

타입 검사와 lint를 통과했지만 읽는 사람이 `url`이 언제 바뀌는지 따라가야 합니다. `{ shas, next }`를
반환하고 호출부에서 대입하는 형태로 고쳤습니다. 리뷰를 받는 코드에서 한 줄 아끼려고 흐름을 숨길
이유가 없었습니다.
