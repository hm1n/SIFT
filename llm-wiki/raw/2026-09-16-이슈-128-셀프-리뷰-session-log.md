### P2-1 · 레퍼런스 대조 테스트가 짧은 문구를 잡지 못했습니다

`allCopyText()`가 문구 363개를 하나로 이어 붙인 뒤 `toContain`합니다. 두 자짜리 `취소`는 전혀 상관없는 곳에 들어 있기만 해도 통과합니다.

실험으로 확인했습니다. 취소 버튼 둘을 `그만두기`로 바꿨는데 51개가 모두 통과했습니다. 살려 준 것은 `auth.ts`의 OAuth 오류 문구 "GitHub 권한 승인을 **취소**했습니다"였습니다. 그대로 쓰기로 한 33개 중 14개가 여덟 자 이하로 같은 상태였습니다.

반대쪽도 과합니다. `not.toContain`은 상관없는 화면의 문구가 레퍼런스 문자열을 품기만 해도 깨집니다.

표에 `at` 필드를 더해 그 문구를 실제로 그리는 상수를 직접 들게 했습니다. `at`이 있으면 `toBe`로 맞추고, 없으면 기존 검색을 씁니다. 긴 문장은 우연히 겹칠 일이 없어 검색으로 남겼습니다. 검색에만 기대는 항목에 짧은 문구가 다시 들어오면 별도 테스트가 막습니다.

같은 실험을 다시 돌려 이번에는 `expected '그만두기' to be '취소'`로 실패하는 것을 확인했습니다.

### P2-2 · `src/copy/` 안에 문구가 다시 복제됐습니다

위키가 "복제 14건 → 0건"이라고 적었는데 세어 보니 22건이었습니다. 파일을 넘나드는 것만 10쌍입니다.

화면별로 파일을 나눈 것이 원인입니다. 사이드바의 `← Repository 변경`과 분석 화면의 같은 버튼이 각각 `shell.ts`와 `repository.ts`에 들어갔습니다. 한쪽만 고치면 두 버튼이 갈립니다.

**교차 import 그물 대신 `shared.ts` 한 파일**을 골랐습니다. 여덟 개의 import 간선을 만드는 것보다 "여러 화면이 함께 쓰는 문구" 한 자리가 읽기 쉽고, import 방향도 하나입니다.

남은 13건은 합치지 않고 남겼습니다. **글자가 같을 뿐 뜻이 다른 경우**라 합치면 한쪽을 다시 쓸 때 다른 쪽이 따라옵니다. 오류 분류가 다른데 문구가 같은 것(`unknown_sha`/`unrelated_sha`), 라우트가 다른데 문구가 같은 것, 그리고 이탈 확인의 머무르기 버튼과 저장본 열기 버튼이 여기 해당합니다. 뒤 둘은 지금 글자가 같지만 조작이 다르므로 `shared.ts` 머리말에 판별 기준으로 적었습니다.
