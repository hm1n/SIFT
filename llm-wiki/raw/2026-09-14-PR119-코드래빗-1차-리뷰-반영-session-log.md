# PR #119 코드래빗 1차 리뷰 반영 세션 로그

`coderabbit review --agent --base develop`을 한 번 돌렸습니다. 지적 3건이고 도구 등급은 전부 minor입니다. 이 프로젝트 기준으로 다시 판정하고 근본 원인별로 묶었습니다.

## 묶음 A — 시간 칸의 의미가 계약에서 뭉개졌습니다

지적은 하나였습니다. `in-memory-store.ts`의 `getInterview`가 `openedAt`을 갱신하지 않는다는 것입니다.

같은 함수와 데이터 흐름을 다시 읽고 **지적되지 않은 결함 두 개**를 함께 찾았습니다. 근본 원인은 스키마에 시간 칸이 셋인데 계약에는 하나만 있다는 것이었습니다.

- `appendTurn`이 어떤 시각도 갱신하지 않아 `updated_at`이 계약에 아예 없었습니다.
- `InterviewListItem`에 `updatedAt`이 없어 정의서 사용자 흐름 1번의 "마지막으로 이어간 시각"을 그릴 수 없었습니다.

등급은 P1으로 올렸습니다. 지금 계약대로면 `openedAt`이 생성 시각에 한 번 박히고 영원히 그대로라서, 90일 자동 정리가 매일 여는 인터뷰도 만든 지 90일이면 지웁니다. 등급표의 "데이터 손실이나 누락"입니다.

호출 지점이 아직 없어 당장 오동작하지는 않으므로 P2로 볼 여지가 있었습니다. 그런데 `AGENTS.md`의 P2 예외 "이번 Issue의 Goal이나 Constraints를 직접 위반하는 경우"에 걸립니다. 이 이슈의 Goal이 뒤 이슈가 같은 질문을 반복하지 않도록 계약을 확정하는 것인데, 데이터를 잃는 계약을 넘기면 Goal을 못 지킵니다.

`getInterview`가 읽기인데 쓰기를 하는 것이 걸려서 이름을 `openInterview`로 바꾸거나 갱신을 호출자에게 맡기는 선택지를 함께 제시했고, 사용자가 지금 모양대로 가기로 했습니다. 호출자에게 맡기면 갱신을 빠뜨린 경로가 남고, 실제 구현에서는 `update ... returning`으로 한 문장에 끝나기 때문입니다.

세 칸의 뜻을 인터페이스 주석에 적고 회귀 테스트 3건을 추가했습니다. 열면 `openedAt`이 갱신되고 90일이 지난 인터뷰도 정리 대상에서 빠지는 것, `appendTurn`이 `updatedAt`만 갱신하는 것, 버전 충돌로 저장하지 않으면 `updatedAt`도 그대로인 것입니다.

## 묶음 B — 테스트가 주변 환경에 의존합니다

`client.test.ts`가 `DATABASE_URL`이 없다는 것을 전제로 판정하는데 셸에 값이 있으면 깨집니다. 재현했습니다.

```
DATABASE_URL=... npx vitest run src/lib/db/client.test.ts
→ Tests  1 failed | 5 passed
```

등급은 P2입니다. merge blocker는 아니지만 수정 비용이 매우 작아 `AGENTS.md` 예외로 같은 PR에서 반영했습니다. 원래 값을 저장했다가 되돌리고, 원래 없던 변수는 없는 상태로 되돌립니다. 환경변수가 있는 상태와 없는 상태 양쪽에서 6건 통과를 확인했습니다.

같은 성격의 기존 코드를 찾아봤습니다. `auth-session.test.ts`와 `callback/route.test.ts` 등도 `afterEach`에서 환경변수를 무조건 지웁니다. 다만 이들은 `beforeEach`에서 값을 확정해 두어 결과가 환경에 따라 달라지지 않습니다. 이번 PR이 만든 것이 아니고 지금 깨지지도 않아 backlog 2번으로 분리했습니다.

## 묶음 C — 스키마 스크립트 재시도

`apply-schema.mts`에 지수 backoff 재시도를 넣으라는 지적입니다. P3으로 판정하고 backlog 1번으로 분리했습니다.

반영하지 않은 이유는 연결 타임아웃을 두 번 관찰했지만 원인을 확인하지 않았기 때문입니다. 지금 재시도 횟수와 간격을 고르면 근거 없는 상수를 정하는 것이 되고, `AGENTS.md`의 "추측성 최적화를 먼저 적용하지 않습니다"에 어긋납니다. 수동으로 돌리는 개발 스크립트라 다시 실행하면 되는 점도 있습니다.
