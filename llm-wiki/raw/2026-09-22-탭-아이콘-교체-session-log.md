# 2026-09-22 탭 아이콘 교체 세션 로그

브라우저 탭 아이콘을 Next 기본 파일에서 서비스 로고로 바꾼 경위입니다. 도달한 계약은 `wiki/2026-09-10-디자인-토큰과-공통-셸.md` 2절의 `탭 아이콘`에 있습니다. 이슈 없이 사용자 요청으로 시작했습니다.

## 1. 시작 상태

`src/app/favicon.ico`가 create-next-app이 넣어 준 파일 그대로였습니다. 26KB에 16·32·48·64 네 크기가 들어 있는 Next 기본 아이콘입니다. 서비스와 무관한 아이콘이 탭에 떠 있었습니다.

로고는 `src/components/shell/sift-mark.tsx`의 `SiftMark` 하나입니다. 32×32 좌표계에 원 25개이고, 바깥 12개가 투명도 0.15~0.17, 안쪽이 0.23~0.32, 오른쪽 아래 한 점만 반지름 2.5에 투명도 1입니다. 흩어진 점 가운데 하나가 선명해지는 그림입니다.

## 2. 16px 실측

"기존 로고를 활용해 달라"는 요청이었지만, 마크의 값을 보고 작은 크기에서 살아남지 못할 것으로 보여 먼저 렌더해 봤습니다. sharp(`next`의 전이 의존성)로 SVG를 16px PNG로 굽고 10배로 확대해 눈으로 확인했습니다.

| 후보 | 16px에서 보이는 것 |
| --- | --- |
| A. 원본 그대로 | 흐린 점들이 전부 사라지고 진한 점 하나만 희미하게 남습니다. 거의 빈 칸입니다. |
| B. 투명도만 2.6배 | 옅은 회색 얼룩입니다. 크기 문제라 대비로는 풀리지 않습니다. |
| D. 점을 25개→13개로 솎고 키움 + 다크 배경에 흰 점 | 선명한 점이 살고 주변 결이 남습니다. 밝은 탭과 어두운 탭 양쪽에서 같게 보입니다. |
| E. D와 같은 단순화, 배경 없이 검정 점 | 밝은 탭에서는 읽히고 어두운 탭에서는 묻습니다. |

원인은 명확합니다. 점 하나의 지름이 32 좌표계에서 3 남짓이라 16px로 줄이면 1.5px가 되고, 투명도 0.17을 곱한 뒤 안티에일리어싱을 거치면 배경과 구분되지 않습니다.

후보 넷을 16·32px 실제 크기와 확대본, 밝은/어두운 배경에 나란히 놓은 비교용 HTML을 scratchpad에 만들어 사용자에게 경로를 전달했습니다. 저장소에는 남기지 않았습니다.

## 3. 사용자 결정

셋을 물었고 답은 이렇습니다.

| 물은 것 | 권고 | 결정 |
| --- | --- | --- |
| 아이콘 모양 | D(다크 배경 + 흰 점, 단순화) | **A. 원본 마크 그대로** |
| 범위 | SVG + ICO 폴백 | 같음 |
| 작업 분리 | 별도 브랜치와 이슈 | **이 브랜치에 커밋만 따로** |

모양은 권고와 다릅니다. 화면 로고와 파비콘을 다르게 두지 않는 쪽을 고른 것이고, 탭에서 흐리게 보이는 것은 실측을 보고 받아들인 결과입니다. 이 사실을 위키에 그대로 적었습니다. 나중에 아이콘이 안 보인다는 말이 나왔을 때 실측이 없어서 그런 것이 아님을 남겨 두기 위해서입니다.

## 4. 구현

**SVG.** `sift-mark.tsx`에서 원을 정규식으로 뽑아 `src/app/icon.svg`를 생성했습니다. 손으로 옮기면 값이 어긋날 수 있어서입니다. 컴포넌트는 `currentColor`인데 파비콘에는 부모가 없어 `#0a0a0a`로 고정했습니다.

**ICO.** `icon.svg`를 16·32·48 PNG로 굽고 ICO 컨테이너로 묶었습니다. 헤더 6바이트, 항목 16바이트씩, 그 뒤에 PNG 데이터를 이어 붙이는 단순한 형식이라 새 의존성 없이 만들 수 있었습니다. 크기가 하나뿐이면 브라우저가 늘리거나 줄여서 뭉갭니다.

**생성 스크립트를 두지 않았습니다.** sharp가 `next`의 전이 의존성이라, 스크립트를 `scripts/`에 남기면 직접 의존성이 아닌 패키지에 기대는 코드가 저장소에 들어옵니다. 로고가 바뀌는 빈도도 낮습니다. 산출물만 커밋하고 만드는 절차를 위키에 적었습니다. 로고가 자주 바뀌게 되면 sharp를 devDependencies로 올리고 스크립트로 빼는 것이 맞습니다.

**다크 탭 반전은 임의로 넣었습니다.** 검은 점은 어두운 탭 띠에서 묻습니다. SVG 안에 `prefers-color-scheme: dark`를 두어 `#fafafa`로 뒤집습니다. 모양은 건드리지 않았습니다. 사용자의 "원본 그대로"를 모양에 대한 결정으로 읽었고, 구현 후 보고에 적어 되돌릴 수 있게 했습니다. ICO에는 미디어 쿼리가 없어 이 반전이 없습니다.

## 5. 테스트

`src/app/icon.test.ts` 두 건입니다.

- `icon.svg`의 원 25개가 `sift-mark.tsx`의 원과 좌표·반지름·투명도까지 같은지 대조합니다. 두 파일이 갈라져도 화면은 멀쩡하고 빌드도 통과해서, 탭을 직접 보지 않으면 드러나지 않습니다.
- `favicon.ico`의 헤더를 읽어 16·32·48 세 크기가 있는지, 각 항목이 PNG로 시작하고 길이가 파일 안에 들어오는지 봅니다.

`shell.test.ts`가 Open Graph 이미지의 PNG 헤더를 읽는 방식과 같은 계열입니다.

## 6. 확인한 것

- dev 서버 `<head>`에 링크 둘이 나갑니다. `/favicon.ico` `sizes="48x48" type="image/x-icon"`과 `/icon.svg` `sizes="any" type="image/svg+xml"`입니다. 두 주소 모두 200이고 Content-Type이 맞습니다.
- ICO에서 16px 항목을 꺼내 확대해 실제 그려지는 모습을 확인했습니다. 2절의 A와 같습니다.
- 테스트 116파일 2,155건, lint, typecheck 통과.

## 7. 남은 것

- 실제 브라우저 탭에서의 모습은 배포 뒤에 봐야 합니다. Safari가 ICO를 고르는지, 다크 테마 탭에서 SVG 반전이 도는지 확인하지 않았습니다.
- iOS 홈 화면용 `apple-icon`은 범위 밖으로 두었습니다.
- 탭에서 아쉬우면 2절의 D나 E로 바꾸는 것은 파일 두 개 교체입니다.
