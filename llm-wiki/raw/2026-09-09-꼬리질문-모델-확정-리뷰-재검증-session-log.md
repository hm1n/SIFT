# 꼬리 질문 모델 확정 재검증 라운드 (이슈 #79 · PR #85)

`raw/2026-09-09-꼬리질문-모델-확정-리뷰-1차-session-log.md`를 이어받습니다. 1차 반영이 새 문제를
만들지 않았는지, 앞 라운드의 P1이 실제로 닫혔는지를 확인한 기록입니다.

## 1. 받은 지적

1건입니다. 도구 등급은 P1입니다.

`src/features/interview/question-generation.ts`의 모델 상수 주석이 폐기한 회차의 값을 그대로 들고
있었습니다. 위키와 세션 로그는 정정본 값으로 갱신했는데 코드 주석만 61/120, 12,204토큰,
0.03398~0.03437달러, 12.7~29.6퍼센트로 남아 있었습니다.

**앞 라운드의 P1이 닫히지 않은 것으로 봅니다.** 묶음 C는 "측정 회차를 섞어 수치를 냈다"였고, 그
묶음의 범위에 코드 주석이 들어 있어야 했습니다. 위키와 노션과 PR 본문은 훑었는데 프로덕션 코드의
주석은 훑지 않았습니다.

## 3. 등급 판정

**P1입니다.** 도구 등급과 같습니다. 값이 틀린 것이 아니라 앞 라운드에서 닫았다고 보고한 P1이 실제로
닫히지 않은 상태였고, 프로덕션 코드의 모델 선택 근거가 위키와 서로 다른 값을 말하고 있었습니다.

`AGENTS.md`는 직전 수정이 만든 P1이 계속 나오면 묶음 범위가 여전히 좁다는 신호라고 적고 있습니다.
이번이 그 경우입니다. 문서만 고치고 코드 주석을 빠뜨린 것이므로 묶음 C의 범위가 좁았습니다.

## 4. 반영

수치를 고치는 것으로 끝내지 않았습니다. 같은 드리프트가 다시 일어나지 않도록 두 값을 문장에서
상수로 옮겼습니다.

- `INTERVIEW_QUESTION_OBSERVED_MAX_OUTPUT_TOKENS = 316`을 더했습니다. 관측된 최대 출력을 주석
  문장 세 곳에 되풀이해 적던 것을 상수 한 곳으로 모았습니다. 회귀 테스트가 출력 상한과의 관계를
  붙들므로, 실측을 다시 돌려 값이 바뀌면 고칠 자리가 한 곳입니다.
- 토큰당 바이트를 적던 자리도 숫자 대신 `INTERVIEW_QUESTION_BYTES_PER_OUTPUT_TOKEN`을 가리키게
  바꿨습니다.

지연과 캐시와 비용 수치는 상수로 옮길 자리가 없어 주석에 그대로 두되 정정본 값으로 고쳤습니다.

회귀 테스트는 `question-generation.test.ts`의 "상한이 이력 항목 상한 안에서 유도된 값이다"를
고쳐 관측 최대를 상수에서 읽게 했습니다. 숫자를 손으로 적던 단언이 상수를 비교하는 단언이 됐으므로,
관측값과 상한이 따로 움직이면 테스트가 먼저 깨집니다.

## 5. 확인

- 폐기한 회차의 수치가 `src/features/interview` 아래에 남아 있지 않은 것을 확인했습니다.
- 전체 테스트 914개 통과, lint 통과, typecheck는 이 브랜치와 무관한 `LayoutProps` 한 건만 남습니다.
