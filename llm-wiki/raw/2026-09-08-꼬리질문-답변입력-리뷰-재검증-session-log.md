# PR #82 Codex 재검증 결과와 반영

`raw/2026-09-08-꼬리질문-답변입력-리뷰-1차-session-log.md`를 이어받습니다. 1차 P1을 반영한 `7d45aa3`에 `@codex review`를 한 번 더 걸었습니다.

## 1. 결과

1차 P1은 다시 지적되지 않았습니다. 새 지적 1건이 나왔습니다.

`use-interview-stream.ts`의 `submitAnswer`가 `text.trim()`한 값을 화면과 이력에 저장한다는 지적입니다. 들여쓰기로 시작하는 Markdown 코드 블록 답변은 앞 공백이 지워져 평문이 되고, 사용자가 쓴 것과 다른 답변이 화면과 요청 이력에 남습니다. Codex 등급은 P1입니다.

## 2. 출처와 등급

이 결함은 첫 구현 `91df92a`에 있던 것이고 직전 수정이 만든 것이 아닙니다. 묶음 범위가 좁았다는 신호로 읽지 않습니다.

이 프로젝트 기준으로는 P2로 다시 판정했습니다. 들여쓰기 코드 블록은 펜스 코드 블록에 비해 드물고, 답변이 사라지는 것이 아니라 앞뒤 공백만 달라집니다. 다만 수정이 `trim()` 호출 위치를 바꾸는 한 줄이라 수정 비용이 매우 작은 경우의 예외를 적용해 같은 PR에서 반영했습니다. 이슈 #77 Goal의 "제출한 답변이 즉시 화면의 대화에 남는다"는 문장은 사용자가 쓴 그대로 남는 것을 뜻하므로 이 예외와도 맞습니다.

## 3. 반영

- 빈 답변 판정에만 `trim()`을 쓰고 저장과 전송은 원문 그대로 합니다.
- 화면의 바이트 측정도 원문으로 바꿔 훅과 같은 값을 잽니다.
- 회귀 테스트는 4칸 들여쓰기 두 줄 답변이 메시지와 요청 이력에 그대로 남는지 확인합니다. 기존 테스트가 `"  첫 답변  "`이 `"첫 답변"`으로 저장된다고 고정하고 있었으므로 그 기대를 바꿨습니다.
- 테스트 875개, lint, typecheck 통과.

## 4. 종료

재검증에서 나온 지적은 P2이고 같은 PR에서 반영했습니다. 지침에 따라 새 P2 때문에 라운드를 더 늘리지 않고 여기서 리뷰를 종료합니다. 1차 1회, 재검증 1회, 지적은 각 1건입니다.
