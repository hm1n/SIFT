# 2026-09-18 회원 탈퇴 구현 세션 로그

이슈 #145를 구현한 세션의 경위입니다. 도달한 계약은 `wiki/2026-09-18-회원-탈퇴와-연결-해제.md`에 있고, 이 파일에는 무엇을 확인하고 무엇을 접었는지를 시간순으로 적습니다.

## 1. 이슈를 읽고 계획을 세웠습니다

이슈가 "정확한 엔드포인트와 필요한 인증 방식은 확인이 필요합니다"로 남겨 둔 것을 먼저 확인했습니다.

- GitHub REST 문서 `rest/apps/oauth-applications`에서 `DELETE /applications/{client_id}/grant`를 확인했습니다. 문서가 밝히는 상태 코드는 204와 422뿐입니다. 효과는 "Deleting an application's grant will also delete all OAuth tokens associated with the application for the user"입니다.
- Basic 인증은 그 문서에 없었습니다. `rest/authentication/authenticating-to-the-rest-api`에서 "You will use the app's client ID as the username and the app's client secret as the password"를 확인했습니다. 한 문서만 보고 인증 방식을 정했으면 401을 받고 나서 원인을 찾았을 것입니다.
- 레퍼런스 디자인(`Chat Interface Design/src/App.tsx`)에 계정 메뉴의 `Delete account`와 한국어 문구 셋이 이미 있는 것을 확인했습니다. 화면 구조를 새로 정하지 않고 그 자리를 썼습니다. 디자인 개편 backlog 3번이 "MVP 범위 밖이고 삭제할 서버 저장 데이터도 없다"고 미뤄 둔 항목인데, 그 뒤 이슈 #115와 #116이 저장을 만들어 전제가 바뀌었습니다.

## 2. 문구를 세 번 고쳤습니다

이 세션에서 가장 여러 번 뒤집힌 결정입니다.

1. 처음에는 `데이터 전체 삭제`를 추천했습니다. 근거는 이 서비스에 지울 회원 레코드가 없고 GitHub 계정도 그대로 남는다는 것이었습니다.
2. 사용자가 "회원 탈퇴나 Sign Out 정도로 쓰면 되지 않나"라고 물었습니다. `Sign Out`은 기각했습니다. 계정 메뉴에 이미 `로그아웃`이 있고, 되돌릴 수 있는 조작과 되돌릴 수 없는 조작이 한 이름을 쓰면 안 됩니다.
3. 다른 후보를 표로 제시했습니다. `기록 전체 삭제`, `내 기록 모두 삭제`, `저장된 데이터 삭제`, `연결 해제와 기록 삭제`입니다. `기록 전체 삭제`를 추천했습니다. 레퍼런스의 경고 문구가 이미 "모든 기록이 삭제됩니다"라 어휘가 이어진다는 이유였습니다.
4. 사용자가 "기록을 다 삭제하고 GitHub 연결도 해제하는 거면 일반적으로 생각하는 회원탈퇴 맞지 않나"라고 다시 물었습니다. 이 지적이 맞습니다. 회원 레코드가 없다는 것은 내부 사정이고, 사용자가 보는 결과는 데이터가 모두 사라지고 서비스가 GitHub에 접근할 수 없게 되는 것입니다. 앞선 추천의 근거가 사용자 관점이 아니라 구현 관점이었다는 것을 인정하고 `회원 탈퇴`로 정했습니다.

확인 단계 문구도 한 번 줄였습니다. 처음에는 "다시 로그인하면 빈 상태로 시작합니다"를 세 번째 줄로 넣었습니다. 탈퇴가 다시 들어올 수 없다는 뜻으로 읽힐 수 있다는 이유였는데, 사용자가 빼라고 해서 두 줄로 확정했습니다.

이 결정 때문에 이용약관 2번에 문장 하나를 더했습니다. 그 절이 "별도의 회원 가입 없이"로 시작하는데 탈퇴만 있으면 짝이 맞지 않습니다.

## 3. 로그아웃의 토큰 해제를 범위 밖으로 두었습니다

이슈의 Why는 "로그아웃이 GitHub 토큰을 무효로 만들지 않습니다"를 문제로 적었지만 Goal은 권한 해제를 탈퇴에만 걸었습니다. 두 읽기가 다른 작업을 낳으므로 사용자에게 물었고 이번 범위 밖으로 정했습니다.

근거는 비용입니다. grant를 지우면 그 사용자의 토큰이 전부 죽고 승인된 앱 목록에서도 사라지므로, 로그아웃마다 지우면 다음 로그인마다 권한 승인 화면을 다시 봐야 합니다. 쿠키가 사라진 뒤에도 토큰이 발급 후 8시간 안에서는 살아 있다는 사실은 남습니다.

## 4. 접은 대안

- **토큰 하나만 지우는 `DELETE /applications/{client_id}/token`.** 지금 브라우저의 세션만 끊고 다른 기기에서 받아 둔 토큰은 남습니다. 권한을 끊었다고 말할 수 없습니다.
- **CTE로 지운 인터뷰 수까지 세기.** 삭제 전 스냅샷을 읽는 CTE를 얹으면 인터뷰 수를 셀 수 있습니다. 접은 이유는 둘입니다. 인터뷰는 분석 없이 존재할 수 없으므로 분석 수만으로 빈 계정을 가를 수 있고, 집계 한 줄을 읽는 구현은 결과가 없을 때 무엇을 돌려줄지 정해야 하는데 그 분기가 실제로는 도달하지 않습니다. `returning id`의 줄 수를 쓰면 두 문제가 함께 없어집니다.
- **저장 계층이 아무것도 돌려주지 않기.** 가장 짧지만 빈 계정을 가를 값이 사라집니다. 이슈 Constraints가 Empty 상태를 함께 구현하라고 요구합니다.
- **결과를 메뉴 안에서 보여 주고 사용자가 눌러서 이동하기.** 쿠키가 이미 사라진 화면에 남게 됩니다. 사용자가 메뉴를 닫으면 로그인 상태로 보이는 화면에서 모든 요청이 401로 답합니다. 표시를 주소에 실어 바로 로그인 화면으로 보내는 쪽을 골랐습니다.
- **`classifyErrorResponse`를 그대로 재사용하기.** 그 함수는 404를 `repo_not_found`로, 401을 `auth_revoked`로 옮깁니다. 이 경로에서는 404가 "이미 해제됨"이고 401이 "서버 설정 문제"라 뜻이 반대에 가깝습니다. 요청 한도 판별만 `rate-limit.ts`로 떼어 공유했습니다.

## 5. 구현과 커밋

커밋 여섯 개로 나눴습니다. 저장 계층, 요청 한도 판별 분리, grant 해제 호출, 라우트, 화면, 문서입니다. 한도 판별 분리를 따로 둔 이유는 동작이 바뀌지 않는 이동이라 리뷰에서 기능 변경과 섞이지 않아야 한다는 것입니다.

`neon-store.test.ts`의 소유자 판정 표에 새 연산을 넣을 때 한 번 막혔습니다. 표의 모든 연산이 같은 가짜 실행기를 쓰는데, 집계 한 줄을 읽는 구현은 빈 결과에서 첫 줄에 접근합니다. 이 문제가 4번의 CTE 대안을 접는 근거가 되었습니다. `returning id` 방식은 빈 결과에서 0을 돌려주므로 표에 그대로 들어갑니다.

## 6. 자체 리뷰에서 셋을 고쳤습니다

사용자가 PR 전에 `/ponytail` 자체 리뷰를 요청했습니다.

- 라우트가 `revoke`를 매개변수로 받는데 예외를 막지 않았습니다. 지금 구현은 전송 실패까지 값으로 돌려주지만 타입이 그것을 보장하지 않습니다. 던지면 이미 끝난 삭제가 500으로 보고되고 쿠키도 남습니다. `catch`로 `network` 실패로 접었습니다.
- `reference-ko.test.ts`의 `다시 시도` 대조 표에서 상수 둘이 빠져 있었습니다. 제가 더한 `ACCOUNT_MENU_COPY.withdrawRetry`와, 이전부터 빠져 있던 `GLOBAL_ERROR_COPY.retry`입니다. 표에 없는 상수는 검사를 받지 않습니다.
- 표시 기본값을 `withdrawnMarker(null)`로 구하고 있었습니다. 상수가 이미 있어서 우회였습니다.

줄이지 않기로 한 것도 적어 둡니다. 표시 넷은 Constraints의 Empty 요구 때문에 유지했고, 해제 실패 이유 다섯 갈래는 `network`와 `config_missing`이 상태 코드를 갖지 않아 로그 판별에 필요합니다. 확인 버튼에 공용 `Button`을 쓰지 않은 것은 208px 메뉴의 12px 버튼이라 크기가 맞지 않고, 같은 성격인 저장된 인터뷰의 삭제 확인도 자기 CSS를 쓰기 때문입니다.

## 7. 리뷰 1라운드

사용자가 다른 세션에 리뷰를 맡겨 결과를 가져왔습니다. 지적 3건이고 유효 2건입니다.

- **P1.** `revokeGitHubGrant`의 `fetch`에 제한 시간이 없었습니다. 이 호출은 데이터를 지운 뒤에 오므로, GitHub이 응답도 실패도 하지 않으면 결과 안내와 쿠키 삭제가 함께 멈춥니다. 삭제는 끝났는데 로그인 상태로 남는 것이 가장 나쁜 조합입니다. `AbortSignal.timeout` 10초를 걸었습니다.
- **P2.** 실패 안내의 취소 버튼이 재시도 중에도 눌렸습니다. 한 줄이라 같은 PR에서 고쳤습니다.
- **기각.** CodeRabbit이 404를 실패로 분류해야 한다고 했습니다. 지울 grant가 없으면 권한도 남지 않아 목표가 이미 이뤄진 상태이므로 계약을 그대로 두었습니다.

묶음을 다시 읽다가 지적되지 않은 같은 성격의 결함을 하나 더 찾았습니다. 브라우저 `fetch`에도 기본 제한 시간이 없어서, 응답이 오지 않으면 버튼이 `탈퇴 중…`에서 멈춥니다. 그 사이 바깥 클릭으로 메뉴가 닫히지 않게 제가 막아 둔 탓에 빠져나올 자리가 없었습니다. 30초 제한 시간을 함께 두었습니다.

## 8. 확인하지 못한 것

- **`scripts/verify-neon-store.mts`를 돌리지 못했습니다.** 이 워크트리에 `.env.local`이 없어 접속 문자열이 없습니다. 질의문이 실제 Postgres에서 도는지는 이 스크립트만 확인할 수 있습니다.
- **실제 GitHub grant 해제를 검증하지 못했습니다.** 실행하면 사용자 계정의 실제 데이터가 지워지고 권한이 끊기므로 손대지 않았습니다. 손으로 확인하는 절차는 위키 문서에 적었습니다.
- **전체 스위트 실행 한 번에서 한 파일 2건이 실패했습니다.** 출력을 잘라 어느 테스트인지 남기지 못했고, 이후 전체 7회 연속 통과라 재현하지 못했습니다. jsdom 비동기 테스트의 타이밍 흔들림으로 보이지만 단정할 근거가 없습니다. 다음에 같은 증상이 나오면 실패 출력을 파일로 남겨야 합니다.

## 9. 도구에서 겪은 것

긴 파일을 bash heredoc으로 쓰려는 시도가 두 번 실패했습니다. 두 경우 모두 셸이 heredoc 본문을 명령으로 읽어 따옴표가 맞지 않는다고 멈췄습니다. 같은 모양을 짧은 내용으로 다시 만들어 보았을 때는 재현되지 않아 원인을 좁히지 못했습니다. 긴 파일은 파일 쓰기 도구로 만들고, 기존 파일 수정은 앵커를 확인하는 파이썬 스크립트로 처리해 진행했습니다.
