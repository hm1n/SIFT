# 화면 문구 한국어 전환 세션 로그

2026-09-15. 이슈 #128 구현입니다. 결론은 `wiki/2026-09-15-화면-문구-한국어-전환.md`에 있습니다. 같은 날 이어진 레퍼런스 대조와 문구 중앙화는 `2026-09-15-화면-문구-레퍼런스-대조와-중앙화-session-log.md`에 있습니다.

## 진행 순서

이슈를 읽고 목표를 보고한 뒤, 사용자가 레퍼런스 위치(`C:\Users\user\Desktop\Chat Interface Design`)를 알려 주며 바로 작업을 시작하라고 했습니다.

레퍼런스에서 읽은 것은 둘입니다. `src/imports/pasted_text/localization-spec.md`(번역 경계 규칙)와 `src/App.tsx`의 `TRANSLATIONS.ko` 블록(387~501행)입니다. **나머지 스펙 6개는 읽지 않았습니다.** 로컬라이제이션 작업이니 `localization-spec.md`면 충분하다고 판단했는데, 이 판단이 뒤에 문제가 됩니다.

문구 교체는 화면 묶음 단위로 진행했습니다.

1. 공용 셸과 로그인
2. Repository 선택과 분석
3. 경험 후보
4. 인터뷰 워크스페이스
5. 저장된 인터뷰
6. 서버 오류 문구
7. 줄바꿈 CSS
8. 위키 기록

## 도구 이야기

문구 교체는 파일 하나에 수십 건이라 손으로 하면 누락이 납니다. `old → new` 쌍을 JSON으로 적고 **각 `old`가 정확히 몇 번 나오는지 검증한 뒤** 치환하는 파이썬 스크립트를 스크래치패드에 만들어 썼습니다. 개수가 맞지 않으면 아무것도 쓰지 않고 실패합니다. 이 검증 덕분에 문맥이 비슷한 문자열을 잘못 바꾸는 일이 없었습니다.

작업 트리가 CRLF라 스크립트가 줄바꿈을 보존하도록 만들었습니다. 처음 판에서는 LF로 써서 `git`이 정규화하는 데 기댔는데, 작업 트리와 저장 형식이 갈리는 것이 찜찜해 CRLF 보존으로 고쳤습니다.

Bash 도구의 heredoc이 백슬래시를 처리해 버려 정규식이 든 파이썬 스크립트가 깨졌습니다(`[^"\\]`가 `[^"\]`가 되어 문자 클래스가 안 닫힘). 스크립트는 Write 도구로 쓰고 Bash로는 실행만 하는 식으로 바꿔 풀었습니다. 같은 이유로 큰 JSON도 Write로 만들었습니다.

## 판단이 갈렸던 지점

### `StatusScreen`의 `code`

이슈 Tasks에 "AUTHENTICATING·ERROR/AUTH 상태"가 적혀 있어 상태 코드까지 번역 대상인지 헷갈렸습니다. 이슈 경계표가 "`ERROR / AUTH` 계열 상태 코드"를 developer metadata로 분류한 것을 근거로 **`code`는 영어, `label`과 `sub`는 한국어**로 갈랐습니다. 레퍼런스 스펙 `product-flow-update.md`의 상태 예시(`AUTHENTICATING`, `LOADING REPOSITORIES`, `NO REPOSITORIES`, `ERROR / AUTH`, `ERROR / GITHUB`)가 전부 영어인 것도 확인했습니다.

### mono 폰트가 곧 영어는 아니라는 것

처음에는 `font-family: var(--font-mono)`를 쓰는 선택자를 전부 영어로 두려 했습니다. 실제로 세어 보니 mono 선택자가 60개가 넘고 그중에는 `.collapseButton`(`파일 목록 접기`), `.status`(스트림 상태 문장), `.terms`(약관 문구)처럼 명백한 자연어가 섞여 있었습니다. 기준을 **그 자리가 값인가 말인가**로 바꿨습니다.

`Commits / 02`를 `COMMITS / 02`로 바꾸려다 되돌렸습니다. 대문자 변환은 번역이 아니라 디자인 변경이고, 이슈 Constraint가 디자인 불변입니다. 레퍼런스 스펙(`multi-file-evidence-nav.md`)은 `COMMITS / 03`으로 적고 있어 어긋나지만 이번 범위가 아닙니다.

### `pluralCount` 주변 어순

사용자 결정이 "`pluralCount`는 영어 유지, 호출부를 바꾸지 않는다"였습니다. 그대로 두면 `12 work units excluded for...`의 뒷부분만 한국어가 되어 `12 work units가 ...`처럼 조사가 영어에 붙습니다. 조사를 피하려고 **수량 표현을 문장 끝으로 보내는 어순**을 썼습니다(`한 번에 보낼 수 있는 분량을 넘어 제외한 12 work units`). 호출부는 그대로입니다.

이슈는 호출부가 6곳이라고 적었는데 실제로는 8곳이었습니다. 이슈의 개수가 정확하지 않다는 뜻이므로 "6곳"을 글자 그대로 계약으로 보지 않고 의도(헬퍼를 한국어로 바꾸지 않는다)를 따랐습니다.

### 줄바꿈 CSS를 어디에 둘지

세 안을 놓고 고민했습니다.

1. 화면 모듈마다 자연어 선택자에 직접 적는다 — 15개 모듈에 수십 개 선택자라 누락이 확실합니다.
2. 각 모듈의 루트 선택자에 적고 mono 선택자에서 되돌린다 — 모듈 수만큼 중복됩니다.
3. `globals.css`의 `body`에 한 번 적고 mono 자리에서만 되돌린다 — 두 속성 모두 상속되므로 성립합니다.

3번을 골랐습니다. 다만 이슈 DoD가 "mono 영역에는 `keep-all`이 걸리지 않습니다"라고 명시해서, 상속으로 걸리는 것 자체가 위반으로 읽힐 수 있었습니다. mono 영역 8개 모듈에 명시적 예외를 두어 해결했습니다.

실제로는 mono 영역 대부분이 `white-space: pre`나 `nowrap`이라 두 속성이 무효입니다. 그래도 예외를 적은 이유는 나중에 `white-space`가 바뀌어도 규칙이 남게 하려는 것입니다.

### 서버 문구를 어디까지 따라갈지

이슈 Tasks는 "`app/api/**/route.ts`가 내려보내는 `error.message` 26건"이라고 했습니다. 화면에서 `.message`를 그대로 그리는 자리를 찾아보니 둘뿐이었습니다(`interview-stream-view.tsx:395`, `repository-analysis-view.tsx:410`). 그 둘로 흘러드는 경로를 거슬러 올라가니 라우트가 아니라 `llm-error.ts`·`schema.ts`·`candidate-client.ts`·`question-request.ts`·`question-stream.ts`가 실제 출처였습니다. 라우트만 고치면 화면에 영어가 남으므로 원천까지 옮겼습니다.

반대로 `saved-interviews/request.ts`(16건), `experience-block/request.ts`(18건), `api/interviews/**`(11건), `api/interview/experience-block`의 검증 메시지는 **옮기지 않았습니다.** 화면이 `kind`만 읽고 문구는 따로 쓰기 때문입니다. `src/lib/github/**`를 제외한 이슈 Non-goal과 같은 기준입니다.

`mapInterviewLlmError`의 `context` 인자를 한국어로 바꿀 때 조사 문제가 있었습니다. 문구가 `${context}이 ...`·`${context}에 ...`를 붙이므로 받침으로 끝나는 명사여야 합니다. `질문 생성`·`블록 갱신` 둘 다 받침으로 끝나 성립하고, 그 제약을 파라미터 주석에 적었습니다.

### 이슈 범위 밖이었던 저장된 인터뷰 화면

이슈 Tasks에 없고 Non-goal이 "레퍼런스에만 있는 화면"으로 빼 둔 항목입니다. 그런데 #115가 머지되며 실제 코드에 생겨 있었습니다. 남기면 사이드바는 한국어인데 그 안의 목록은 영어가 되어 Constraint "한 화면 안에 두 언어를 섞지 않습니다"를 정면으로 위반합니다. Non-goal의 조건("레퍼런스에만 있는")이 이미 깨졌다고 보고 함께 옮겼습니다. 완료 보고에 이 판단을 따로 적었습니다.

## 테스트 갱신에서 실패한 시도

영어 문구를 조회하는 테스트가 253건 깨졌습니다. 처음에는 **치환 쌍을 자동 추출해 테스트 파일에 그대로 적용**했습니다. 1,302건이 치환되었는데 결과가 망가졌습니다. `Edit`·`Send` 같은 짧은 단어가 식별자 안에서도 치환되어 `blockEdit`이 `block편집`, `parseBlockEdit`이 `parseBlock편집`이 되었습니다.

되돌리고 규칙을 바꿨습니다. **20자 이상인 문구만 평문 치환하고, 그보다 짧으면 따옴표로 감싼 완전한 리터럴일 때만 치환**합니다. 236건이 바뀌었고 식별자 훼손은 없었습니다.

남은 실패는 `toContain`으로 문구 일부만 보는 단정과 정규식 조회여서 자동으로 잡히지 않았습니다. 실패 메시지를 읽고 치환 쌍을 추가하는 일을 13라운드 반복해 0으로 만들었습니다. 한 번에 다 잡으려 하지 않고 파일 묶음별로 돌린 것이 빨랐습니다.

치환 과정에서 콤마를 하나 지워 `repository-flow.tsx`가 파싱 오류를 냈습니다. 치환 쌍의 `old`에는 뒤따르는 콤마가 있는데 `new`에서 빠뜨린 경우였습니다. typecheck가 바로 잡았습니다.

## 검증하지 못한 것

이슈 DoD의 첫 항목인 **실제 앱 구동 확인은 하지 않았습니다.** GitHub OAuth 세션이 필요해 로그인부터 인터뷰 종료까지 브라우저로 훑지 못했습니다. 검증은 테스트 1,600개와 정적 스윕으로만 했습니다. 특히 `.cardState`의 mono 자간이 한국어에 걸리는 문제는 눈으로 봐야 판단이 되는데, 디자인 불변 Constraint 때문에 손대지 않고 backlog 29번으로 남겼습니다.
