# 디자인 토큰과 공통 셸 PR 리뷰 1차 반영 세션 로그

2026-09-10 PR #99의 Codex 1차 리뷰를 반영한 기록입니다. `raw/2026-09-10-디자인-토큰과-공통-셸-구현-session-log.md`를 이어받습니다. 결론은 `wiki/2026-09-10-디자인-토큰과-공통-셸.md` 3절에 있습니다.

## 1. 지적

라운드 1회, 지적 1건입니다. 도구 등급 P1이고 프로젝트 기준으로도 P1로 판정했습니다. 로그아웃 뒤 비공개 저장소의 후보 목록이 화면에 남는 것은 잘못된 결과가 사용자에게 전달되는 문제이자 권한 문제입니다.

지적된 줄은 `repository-analysis-view.tsx`의 `hasSession` 동기화 분기입니다. 헤더 Sign out이 서버를 다시 그리면 `hasSession`만 바뀌고 `state`와 `analyzedRepository`는 살아 있어 완료된 결과가 남고, 진행 중이던 요청은 나중에 결과를 다시 올립니다. 반대 방향인 `reauthenticate`는 화면만 비우고 서버 헤더를 갱신하지 않아 Account 메뉴가 남습니다.

## 2. 묶음

묶음은 하나입니다. **세션 진위가 서버 쿠키와 화면의 로컬 `hasSession` 두 곳에 있고, 로그아웃 진입점 둘이 각각 한쪽만 갱신하는 것**이 근본 원인입니다. 지적된 줄만 고치면 `reauthenticate` 쪽이 다음 라운드에 다시 나옵니다.

같은 원인으로 지적되지 않았지만 함께 고친 것은 분석 진행 중 로그아웃입니다. 상태를 비우는 것만으로는 이미 떠난 요청이 늦게 부르는 `setState`를 막지 못합니다.

## 3. 반영

- 화면의 로컬 `hasSession` 상태를 없애고 서버가 넘기는 prop만 씁니다.
- `reauthenticate`는 세션 삭제 뒤 분석 상태를 비우고 라우터를 갱신합니다. 헤더의 Sign out과 같은 경로입니다.
- prop이 false로 바뀌는 순간 분석 상태를 비웁니다. 실행 번호는 effect에서 올려 늦게 온 결과를 버립니다.
- 상태 분기 네 개를 `hasSession`으로 감싸 실행 번호가 오르기 전 도착한 결과도 그려지지 않게 했습니다.

### 시도와 실패

- 처음에는 렌더 중 prop 변화를 감지하는 자리에서 실행 번호 ref를 함께 올렸습니다. `react-hooks/refs` lint가 렌더 중 ref 접근을 막아 effect로 옮겼고, 그 사이의 틈은 렌더 게이트로 막았습니다.
- 성공 상태 테스트 fixture를 `candidates: []`로 썼다가 타입과 렌더 양쪽에서 깨졌습니다. `StageBCandidateResult` 형태로 바꿨습니다.

### 회귀 테스트

- 헤더 Sign out으로 세션이 사라지면 완료된 후보 목록을 버립니다.
- 분석 진행 중 세션이 사라지면 늦게 도착한 결과를 화면에 올리지 않습니다.
- 기존 `reauthenticate` 테스트 세 건은 라우터 갱신을 서버 역할로 두고 세션 없는 prop으로 다시 그리는 형태로 바꿨습니다.
