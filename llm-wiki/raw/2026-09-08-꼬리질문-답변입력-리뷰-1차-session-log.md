# PR #82 Codex 1차 리뷰를 반영했습니다

이슈 #77 PR #82의 1차 리뷰 반영 경위입니다. 반영된 결과는 `wiki/2026-09-08-꼬리질문-답변입력-대화누적-화면.md` 3·4절에 있습니다. 앞선 기록은 `raw/2026-09-08-꼬리질문-답변입력-실제-동작확인-session-log.md`입니다.

## 1. 지적

Codex가 `a0926c3`을 보고 P1 1건을 남겼습니다. `use-interview-stream.ts`에서 모델이 낸 질문이 직렬화 4,500바이트를 넘어도 클라이언트가 그대로 확정하고 답변 제출을 연다는 지적입니다. 답변을 제출하면 서버가 `history_too_large`로 거절하는데 그때는 입력란이 비워졌고 답변이 대화에 남아 있으며, 다시 시도가 같은 이력을 다시 보내 같은 거절이 옵니다.

## 2. 묶음과 등급

묶음은 하나입니다. 생성된 질문에 이력 항목 상한 검사가 없다는 것입니다. 서버는 출력 길이를 자르지 않고(`wiki/2026-09-08-꼬리질문-요청계약-후속-backlog.md` 3번) 클라이언트는 `trimInterviewHistory`로 항목 수만 봅니다.

지적되지 않았지만 같은 원인이 드러나는 지점을 두 개 더 찾았습니다.

- `retry()`가 도착 중인 질문만 지웁니다. 413은 첫 청크 전 거절이라 스트리밍 항목이 없고 마지막 항목은 확정된 긴 질문입니다. 아무것도 지우지 않고 같은 이력을 다시 보냅니다.
- `history_too_large`에 안내 문구가 없어 일반 문구가 나갑니다. 이유가 보이지 않습니다. 이 항목은 이슈 #78 범위이지만 이 경로를 막으면 정상 흐름에서 도달하지 않습니다.

등급은 P1로 유지했습니다. 발생 확률은 낮습니다. 실측 질문이 250~350자이고 상한은 한글 약 1,500자입니다. 그러나 발생하면 답변이 대화에 갇히고 복구 수단이 없어 이슈 Goal "생성이 실패해도 답변이 사라지지 않고 그 질문만 다시 시도할 수 있다"를 위반합니다.

## 3. 접은 대안

- 서버에 `maxOutputTokens`를 걸어 근본적으로 없애는 안입니다. 이슈 #77 Constraint "요청 계약과 생성 경로는 건드리지 않는다"를 위반하므로 접었습니다. backlog 3번에 남겼습니다.
- `errors.ts`에 새 오류 종류를 더하는 안입니다. 그 파일은 서버 route와 공유하는 분류라서 클라이언트만의 판정을 섞지 않으려고 접었습니다. 훅 상태 `isLastQuestionTooLong`으로 두고 화면이 기존 오류 박스 자리에서 분기합니다.
- 넘치는 질문을 화면에서 지우는 안입니다. 사용자가 무엇이 왔는지 볼 수 없어 접었습니다. 질문은 남기고 확정만 하지 않습니다.

## 4. 반영

- `completeStreamingMessage`가 `done` 시점에 완성 질문을 `interviewHistoryItemBytes`로 재서 넘치면 `isLastQuestionTooLong`을 켭니다. `canSubmitAnswer`가 거짓이 됩니다.
- `retry()`의 삭제 범위를 "도착 중인 질문"에서 "도착 중이거나 상한 초과인 질문"으로 넓혔습니다.
- 화면은 `error`나 `isLastQuestionTooLong`이면 같은 오류 박스에 그립니다. Error를 두 곳에 그리지 않는 제약을 지킵니다.
- 회귀 테스트를 훅과 화면에 하나씩 넣었습니다. `"가"`를 1,510번 반복한 질문으로 글자 수는 상한 안이지만 바이트는 넘는 경우를 씁니다.
- 첫 반영에서 lint의 `react-hooks/immutability`가 ref를 effect에서 갱신하는 코드를 거절했습니다. ref 선언을 위로 올리고 상태를 바꾸는 자리에서 ref도 함께 바꾸는 방식으로 고쳤습니다.
- 커밋 `1aa0863`. 테스트 874개, lint, typecheck 통과.
