# 인터뷰 저장과 이어가기 후속 backlog

이슈 #115에서 범위 밖으로 분리한 항목입니다. 2026-08-20 코드 리뷰 전략에 따라 새 GitHub Issue를 만들지 않고 이 문서에서 추적합니다.

## 1. 인터뷰 화면 안의 Sessions 드롭다운

디자인 원본의 인터뷰 워크스페이스 헤더에는 `SESSIONS (n)` 드롭다운이 있고, 대화 중에 다른 인터뷰로 곧바로 갈아탑니다. 사용자 결정으로 이번에 넣지 않았습니다.

사이드바만으로 이어가기가 성립하고, 대화 중 전환에는 따로 정해야 하는 것이 둘 있습니다. 전환 시점에 밀린 턴을 어떻게 처리할지(그 인터뷰를 떠나면 그 턴은 영영 밀린 채로 남습니다)와 쓰던 답변을 어떻게 할지입니다. 둘 다 이탈 확인과 같은 성격의 결정이라 함께 정하는 편이 낫습니다.

## 2. 이어가기 화면의 블록 문장 표시 (2026-09-15 해결)

디자인 원본의 `SessionReviewScreen`은 저장된 PAAR 블록의 문장까지 그립니다. 처음에는 기호(`✓`·`●`·`○`)로만 보였습니다. 같은 값을 두 화면이 각자 그리면 어긋난다는 것이 미룬 이유였습니다.

인터뷰 화면의 편집을 이 화면으로 옮기면서 함께 해결했습니다. 편집하려면 고칠 문장이 보여야 하기 때문입니다. 두 화면이 어긋나는 것은 문장과 출처와 충돌을 그리는 부분을 `experience-block/block-sentences.tsx` 하나로 묶어 막았습니다. 두 화면이 각자 그리지 않고 같은 컴포넌트를 부릅니다.

## 3. 이어가기한 인터뷰의 저장소 메타데이터

사이드바 REPOSITORY 칸은 `PRIVATE · TypeScript`를 보입니다. 이 값은 GitHub 목록 조회에서 오고, 저장된 인터뷰에는 owner와 name만 있습니다. 그래서 이어가기로 들어오면 이름만 보입니다.

저장 계층에 칸을 더해 해결하지 않았습니다. 공개 여부와 언어는 저장소에서 바뀔 수 있는 값이라 저장하면 오래된 값을 사실처럼 보이게 됩니다. 목록을 이미 받아 둔 경우에 이름으로 맞춰 채우는 방법이 남아 있지만, 그러려면 이어가기가 GitHub 목록 조회를 기다려야 해서 이번에는 하지 않았습니다.

## 4. 디자인 원본의 새 요소 셋

2026-09-15 갱신본에 이번 이슈와 무관한 요소가 셋 들어왔습니다. 어느 이슈에서 다룰지 정하지 않았습니다.

- **계정 삭제.** 상단 계정 메뉴에 `Delete account`와 확인 단계가 있습니다. 지울 서버 데이터가 이제 실제로 있으므로(분석과 인터뷰), 디자인 개편 backlog 3번("삭제할 서버 저장 데이터도 없습니다")의 전제가 바뀌었습니다.
- **공개 랜딩 페이지.** `sift-landing-page.md` 스펙과 `LandingPage` 구현이 원본에 있습니다. 지금 저장소의 로그인 화면을 대체하는 범위입니다.
- **KO/EN 언어 선택기.** `localization-spec.md`가 헤더에 언어 선택기를 두고 화면 문구 전체를 두 언어로 나눕니다. #92 공통 결정("문구는 영어")을 대체하는 결정이라 화면 거의 전부를 건드립니다.

## 5. 비공개 Repository 코드가 저장된다는 안내

경험을 확정하면 그 시점의 근거 스냅샷이 서버에 저장되고, 거기에는 비공개 Repository의 코드 변경(patch)이 들어 있습니다. 확정 액션 근처에 이 사실을 알릴지 정하지 않았습니다.

이슈 #115의 Tasks에 없고 문구는 화면 결정이라 이번에 넣지 않았습니다. 지금 확정 화면이 이미 "확인 가능·불가" 안내를 여럿 달고 있어 자리를 정하는 데 주의가 필요합니다.
