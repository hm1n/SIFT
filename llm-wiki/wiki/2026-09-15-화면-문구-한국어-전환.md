# 화면 문구 한국어 전환

이슈 #128입니다. 화면의 자연어 제품 문구를 한국어로 옮기고, developer tool 시각 언어를 만드는 영어 요소는 의도적으로 남겼습니다. KO 단일 적용이고 언어 선택 기능은 만들지 않았습니다.

## 왜 뒤집었는가

이슈 #92는 "디자인대로 영어를 씁니다"로 정했고 #93~#98이 그 결정을 따라 화면 문구를 영어로 옮겼습니다. 그 시점에는 레퍼런스에 로컬라이제이션 스펙이 없었습니다. 이후 레퍼런스에 `src/imports/pasted_text/localization-spec.md`가 추가되면서 KO/EN 두 제품 언어와 "번역할 제품 언어 / 번역하지 않을 기술 언어"의 경계가 정의되었습니다. 전제가 바뀌었으므로 결정을 다시 적용했습니다.

한 화면 안에서 언어가 갈리던 것도 이유입니다. AI가 만드는 질문과 PAAR 문장은 `question-prompt.ts`와 `stage-b.ts`의 응답 언어 지시로 이미 한국어인데, 그 대화를 감싸는 화면 문구와 오류 안내와 버튼과 빈 상태는 영어였습니다. 사용자는 한국어로 답변을 쓰면서 영어 UI를 읽었습니다.

## 번역 경계

`localization-spec.md`는 "영어를 없애는 것이 목적이 아니라 번역할 제품 언어와 번역하지 않을 기술 언어를 의도적으로 구분하는 것이 목적"이라고 못박습니다. 그 기준을 이 Repository의 실제 문구에 적용한 결과입니다.

| 구분 | 처리 | 해당 항목 |
| --- | --- | --- |
| 자연어 제품 문구 | 한국어 | 설명, 버튼, 오류 안내, 빈 상태, 플레이스홀더, 확인 문구, `aria-label` |
| Developer metadata | 영어 유지 | `PAAR`, `PROBLEM`/`ANALYZE`/`ACTION`/`RESULT`, `Agent`/`You`, `ERROR / AUTH` 계열 상태 코드, `Authenticating`·`Loading Repositories` 같은 `StatusScreen`의 `code`, `UPDATED 3D AGO`, `PRIVATE` |
| 섹션 라벨 | 영어 유지 | `Repositories`, `Your Contribution`, `Optional`, `Candidates`, `Code / Evidence`, `Files`, `Diff`/`File`, `Selected file`, `No diff body`, `Repository`, `Interviews`, `Experience`, `Why worth discussing`, `Technical topics`, `Repository evidence`, `VERIFIED FROM REPOSITORY` |
| 근거 구분 태그 | 영어 유지 | `Verified`, `Unverifiable`, `AI-selected` |
| Repository 원본값 | 원문 유지 | 파일 경로, 파일명, SHA, PR 번호, 브랜치, 코드, diff, 저장소명, 언어명 |
| 기술 용어 | 한국어 문장 안에서 영어 유지 | WebSocket, TypeScript, API, commit, diff, Repository, rate limit, patch, heuristic |

섹션 라벨과 태그를 영어로 두는 근거는 둘입니다. 레퍼런스 `App.tsx`의 `TRANSLATIONS.ko`가 이 항목들을 번역하지 않고 영어로 남겨 두었고, mono 폰트로 그리는 키워드가 SIFT의 developer tool 컨셉을 만드는 요소입니다.

### `Repository`를 한글로 옮기지 않은 이유

레퍼런스 `TRANSLATIONS.ko`는 `저장소`를 씁니다(`selectRepository: "저장소 선택"`). 이 Repository는 이슈 #128의 경계표를 따라 `Repository`를 영어로 남겼습니다. 코드와 위키와 이슈 본문이 이미 한국어 문장 안에서 `Repository`를 그대로 쓰고 있어, 화면만 `저장소`로 가면 같은 대상을 두 이름으로 부르게 됩니다.

### mono 라벨과 자연어의 경계 판정

`font-family: var(--font-mono)`를 쓰는 선택자가 곧 developer metadata는 아닙니다. 판정은 **그 자리가 값인가 말인가**로 했습니다.

- 값이면 영어: `.sectionLabel`, `.panelHeading`, `.viewMode`, `.sectionCount`, `.code`(상태 코드), `.eyebrow` 중 `Experience`·`Candidates` 같은 라벨
- 말이면 한국어: 같은 mono여도 버튼과 문장인 `.collapseButton`(`파일 목록 접기`), `.saveNoticeAction`(`다시 저장`), `.status`(스트림 상태 문장), `.cardState`(`수집 중`), `.tab`(`인터뷰`), `.terms`(`계속하면 이용약관에 동의하는 것입니다`)

`.eyebrow`는 자리마다 갈립니다. `Experience`는 라벨이라 영어로 두고, `Repository 선택`·`Repository 분석 중`은 화면이 무엇을 하는지 말하는 문장이라 한국어입니다.

## 사용자 결정 사항

| 항목 | 결정 | 반영 |
| --- | --- | --- |
| `pluralCount`(`3 commits`) | 영어 유지 | `candidate-period.ts`의 함수와 호출부 8곳을 그대로 두고 앞뒤 문장만 한국어로 바꿨습니다. `3 experiences 발견`, `한 번에 보낼 수 있는 분량을 넘어 제외한 2 work units`처럼 됩니다 |
| 날짜 표기 | 한국어로 변경 | `candidate-period.ts`의 `Intl.DateTimeFormat` 로케일이 `ko-KR`입니다. `Aug 2026` → `2026년 8월`, `Sep 15, 2026` → `2026년 8월 15일`. `saved-interview-list.tsx`·`saved-interview-screen.tsx`의 `toLocaleDateString`도 같이 옮겼습니다(`Sep 12` → `9월 12일`) |
| `Verified`/`Unverifiable`/`AI-selected` | 영어 유지 | `evidence-verifiability.ts`의 라벨은 그대로 두고 뒤에 붙는 설명 문장만 한국어입니다 |

## 구현 방향

문구를 정의한 자리에서 한국어 리터럴로 교체했습니다. 별도 번역 테이블이나 `t()` 헬퍼를 만들지 않았습니다. KO 단일에서는 간접층이 모든 참조를 한 단계 우회시킬 뿐 얻는 것이 없고, EN을 다시 붙일 때는 언어 선택기·`localStorage` 지속·AI 프롬프트 언어까지 함께 설계해야 해서 지금 만든 구조를 어차피 다시 잡습니다. EN 재도입 시 이 교체를 들어내야 하는 비용은 감수한 결정입니다.

이미 상수로 모여 있던 문구(`EMPTY_COPY`, `ERROR_SUB`, `AUTH_ERROR_COPY`, `CARD_STATE_LABELS`, `GENERATION_ERROR_CAUSE`, `WORK_UNIT_SIGNAL_COPY`, `BLOCK_UPDATE_ERROR_CAUSE` 등)는 그 상수만 고쳤습니다. JSX 안에 직접 쓴 문장은 제자리에서 바꿨습니다.

### 서버 문구까지 옮긴 범위

화면이 `error.message`를 그대로 렌더하므로(`interview-stream-view.tsx`의 오류 박스, `repository-analysis-view.tsx`의 `StatusScreen` sub) 라우트만 빼면 한국어 화면에 영어 오류가 섞입니다. 라우트가 내려보내는 메시지의 **원천**까지 따라가 옮겼습니다.

- `app/api/**/route.ts`가 직접 쓰는 메시지
- `features/interview/llm-error.ts` — `mapInterviewLlmError`가 만드는 메시지. `${context}` 자리에 `"Question generation"`·`"Block update"` 대신 `"질문 생성"`·`"블록 갱신"`을 넘깁니다. 문구가 `이`·`에` 조사를 붙이므로 받침으로 끝나는 명사만 넘겨야 합니다
- `features/experience-candidates/schema.ts`·`candidate-client.ts` — Stage A/B 검증 실패 메시지. `repository-analysis.ts`가 `${error.message}`로 이어 붙여 화면에 그립니다
- `features/interview/question-request.ts`·`question-stream.ts`

`src/lib/github/**`의 내부 Error 메시지는 옮기지 않았습니다. 화면에 도달하지 않습니다. 화면은 `GitHubFetchError.kind`만 읽고 문구는 `errorCopy`·`ERROR_SUB`가 따로 씁니다.

`evidence-snapshot.ts`의 `EvidenceVerifiability.detail`도 옮기지 않았습니다. 화면이 아니라 `question-prompt.ts`가 AI 프롬프트에 싣는 값이고, 이슈 Constraint가 AI 프롬프트를 손대지 않는 것입니다.

## 줄바꿈

`word-break: keep-all; overflow-wrap: break-word;`를 `globals.css`의 `body`에 한 번만 뒀습니다. 두 속성 모두 상속되므로 화면마다 되풀이할 필요가 없습니다. 예전에는 `interview-stream-view.module.css`의 `.log` 하나에만 있었는데, 모든 화면이 한국어를 그리게 되어 한 자리로 올렸습니다.

mono 영역은 각 모듈에서 `word-break: normal; overflow-wrap: normal;`로 되돌립니다. 경로·SHA·코드에는 어절이 없어 어절 단위 금지가 뜻을 갖지 않고, 긴 토큰이 칸을 넘길 때는 끊어야 합니다. 되돌리는 자리는 여덟입니다.

| 모듈 | 선택자 |
| --- | --- |
| `status-screen.module.css` | `.code` |
| `app-shell.module.css` | `.repositoryMeta` |
| `code-panel.module.css` | `.collapsedFilename`, `.directoryLabel`, `.filename`, `.diffPath`, `.commitSelector code`, `.diffLineNumber`, `.diffMark`, `.diffContent` |
| `interview-stream-view.module.css` | `.message code`, `.codeBlock pre`, `.plainCode` |
| `block-sentences.module.css` | `.source` |
| `experience-candidate-detail.module.css` | `.evidenceListMeta` |
| `experience-candidate-list.module.css` | `.exclusionList code` |
| `saved-interview-screen.module.css` | `.commitBadge` |

`white-space: pre`나 `nowrap`이 걸린 자리(`.diffContent`, ellipsis를 쓰는 파일명 계열)는 애초에 줄바꿈이 일어나지 않아 두 속성이 무효입니다. 그래도 예외를 명시한 이유는 나중에 `white-space`가 바뀌어도 규칙이 남아 있게 하려는 것입니다.

## 이슈 범위 밖이었지만 함께 옮긴 것

이슈 #128의 Tasks는 저장된 인터뷰 화면을 열거하지 않았고 Non-goal은 "레퍼런스에만 있는 화면(Sessions 목록, 저장된 인터뷰 불러오기)"을 범위 밖으로 뒀습니다. 그런데 #115가 머지되면서 그 화면들이 실제 코드에 생겼습니다(`saved-interview-list.tsx`, `saved-interview-screen.tsx`). 남겨 두면 사이드바는 한국어인데 그 안의 목록은 영어인 상태가 되어, 이슈 Constraint "한 화면 안에 두 언어를 섞지 않습니다"를 정면으로 위반합니다. 함께 옮겼습니다.

Non-goal의 문장은 "레퍼런스에만 있는 화면"을 가리키는 것이고, 코드에 들어온 뒤로는 그 조건이 성립하지 않습니다.

## 남은 것

- **`aria-label="Repositories"`.** 라디오그룹의 접근성 이름이 화면의 영어 섹션 라벨 `Repositories`를 그대로 씁니다. 라벨이 영어로 남는 한 이름도 같아야 스크린리더 사용자가 보이는 것과 들리는 것을 맞출 수 있어 그대로 뒀습니다.
- **`.cardState`의 `letter-spacing`.** PAAR 카드 상태가 `수집 중`처럼 한국어인데 mono 자간 `0.05em`이 그대로 걸립니다. 디자인을 바꾸지 않는 것이 이번 Constraint라 손대지 않았습니다. 읽기 어렵다는 피드백이 나오면 그때 검토합니다.
- **EN 재도입.** 이번 작업은 KO 단일이라 `LangContext`·언어 선택기·`localStorage` 지속·브라우저 언어 감지를 만들지 않았습니다. `localization-spec.md`의 나머지 절(Language Selector, Language Persistence, Initial Language, Authentication)이 그때의 입력입니다.

## 테스트

영어 문구를 조회하던 테스트를 갱신했습니다. 문구 교체 자체는 회귀 테스트가 아니라 기존 테스트의 기대값 변경이므로 새 테스트를 만들지 않았습니다. 대신 기존 테스트가 전부 통과하는 것으로 화면이 같은 상태를 계속 그리는지 확인합니다. 테스트 1,600개, lint, typecheck 통과입니다.
