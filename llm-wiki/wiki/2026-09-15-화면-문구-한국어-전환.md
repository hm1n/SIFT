# 화면 문구 한국어 전환

이슈 #128입니다. 화면의 자연어 제품 문구를 한국어로 옮기고, developer tool 시각 언어를 만드는 영어 요소는 의도적으로 남겼습니다. KO 단일 적용이고 언어 선택 기능은 만들지 않았습니다.

## 왜 뒤집었는가

이슈 #92는 "디자인대로 영어를 씁니다"로 정했고 #93~#98이 그 결정을 따라 화면 문구를 영어로 옮겼습니다. 그 시점에는 레퍼런스에 로컬라이제이션 스펙이 없었습니다. 이후 레퍼런스에 `src/imports/pasted_text/localization-spec.md`가 추가되면서 KO/EN 두 제품 언어와 "번역할 제품 언어 / 번역하지 않을 기술 언어"의 경계가 정의되었습니다. 전제가 바뀌었으므로 결정을 다시 적용했습니다.

한 화면 안에서 언어가 갈리던 것도 이유입니다. AI가 만드는 질문과 PAAR 문장은 `question-prompt.ts`와 `stage-b.ts`의 응답 언어 지시로 이미 한국어인데, 그 대화를 감싸는 화면 문구와 오류 안내와 버튼과 빈 상태는 영어였습니다. 사용자는 한국어로 답변을 쓰면서 영어 UI를 읽었습니다.

## 번역 경계

`localization-spec.md`는 "영어를 없애는 것이 목적이 아니라 번역할 제품 언어와 번역하지 않을 기술 언어를 의도적으로 구분하는 것이 목적"이라고 못박습니다. 그 기준을 이 Repository의 실제 문구에 적용한 결과입니다.

| 구분 | 처리 | 해당 항목 |
| --- | --- | --- |
| 자연어 제품 문구 | 한국어 | 설명, 버튼, 오류 안내, 빈 상태, 플레이스홀더, 확인 문구, `aria-label` |
| Developer metadata | 영어 유지 | `PAAR`, `PROBLEM`/`ANALYZE`/`ACTION`/`RESULT`, `Agent`/`You`, `ERROR / AUTH` 계열 상태 코드, `Authenticating`·`Loading Repositories` 같은 `StatusScreen`의 `code`, `UPDATED 3D AGO`, `PRIVATE` |
| 섹션 라벨 | 영어 유지 | `Repositories`, `Your Contribution`, `Optional`, `Candidates`, `Code / Evidence`, `Files`, `Diff`/`File`, `Selected file`, `No diff body`, `Repository`, `Interviews`, `Experience`, `Why worth discussing`, `Technical topics`, `Repository evidence`, `VERIFIED FROM REPOSITORY` |
| 근거 구분 태그 | 영어 유지 | `Verified`, `Unverifiable`, `AI-selected` |
| Repository 원본값 | 원문 유지 | 파일 경로, 파일명, SHA, PR 번호, 브랜치, 코드, diff, 저장소명, 언어명 |
| 기술 용어 | 한국어 문장 안에서 영어 유지 | WebSocket, TypeScript, API, commit, diff, Repository, rate limit, patch, heuristic |

섹션 라벨과 태그를 영어로 두는 근거는 둘입니다. 레퍼런스 `App.tsx`의 `TRANSLATIONS.ko`가 이 항목들을 번역하지 않고 영어로 남겨 두었고, mono 폰트로 그리는 키워드가 SIFT의 developer tool 컨셉을 만드는 요소입니다.

### 영어로 남기는 것과 `src/copy/`에 담는 것은 다른 결정입니다

처음에는 "번역 대상이 아니므로 쓰는 자리에 그대로 둔다"로 정하고 `src/copy/`에서 제외했습니다. **이 규칙은 2026-09-16에 뒤집혔습니다.** 라벨이 화면 파일에 흩어지면 두 화면이 같은 라벨을 각자 들게 되고, 한쪽만 고쳤을 때 조용히 갈립니다.

실제로 그랬습니다. `saved-interview-screen.tsx`가 PAAR 블록 이름표를 `block-labels.ts`와 따로 들고 있었습니다. 글자까지 같아서 드러나지 않았지만, 두 번째 블록의 이름 `Analyze`는 설계 문서의 `ALTERNATIVE`를 대체한 값이라(이슈 #92) 한쪽만 바뀌면 인터뷰 화면과 저장본 화면이 같은 블록을 다르게 부릅니다. 기존 테스트는 `"Problem 편집"`을 리터럴로 들어 나머지 세 블록이 갈려도 통과했습니다.

그래서 라벨도 `src/copy/`에 담되 영어로 둡니다. 두 화면 이상이 쓰는 것은 `shared.ts`입니다(`SECTION_EXPERIENCE`, `SECTION_WHY_WORTH_DISCUSSING`, `SECTION_TECHNICAL_TOPICS`, `SECTION_REPOSITORY_EVIDENCE`, `SECTION_INTERVIEWS`, `BLOCK_LABELS`). `block-labels.ts`는 없어지고 `shared.ts`로 들어갔습니다.

화면에 남은 영어는 브랜드 마크 `SIFT` 하나입니다. 제품 이름이라 문구가 아니고, 접근성 이름은 `TOP_HEADER_COPY.homeLabel`에 있습니다.

### `Repository`를 한글로 옮기지 않은 이유

레퍼런스 `TRANSLATIONS.ko`는 `저장소`를 씁니다(`selectRepository: "저장소 선택"`). 이 Repository는 이슈 #128의 경계표를 따라 `Repository`를 영어로 남겼습니다. 코드와 위키와 이슈 본문이 이미 한국어 문장 안에서 `Repository`를 그대로 쓰고 있어, 화면만 `저장소`로 가면 같은 대상을 두 이름으로 부르게 됩니다.

### mono 라벨과 자연어의 경계 판정

`font-family: var(--font-mono)`를 쓰는 선택자가 곧 developer metadata는 아닙니다. 판정은 **그 자리가 값인가 말인가**로 했습니다.

- 값이면 영어: `.sectionLabel`, `.panelHeading`, `.viewMode`, `.sectionCount`, `.code`(상태 코드), `.eyebrow` 중 `Experience`·`Candidates` 같은 라벨
- 말이면 한국어: 같은 mono여도 버튼과 문장인 `.collapseButton`(`파일 목록 접기`), `.saveNoticeAction`(`다시 저장`), `.status`(스트림 상태 문장), `.cardState`(`수집 중`), `.tab`(`인터뷰`), `.terms`(`계속하면 이용약관에 동의하는 것입니다`)

`.eyebrow`는 자리마다 갈립니다. `Experience`는 라벨이라 영어로 두고, `Repository 선택`·`Repository 분석 중`은 화면이 무엇을 하는지 말하는 문장이라 한국어입니다.

## 구현 방향

**두 단계로 진행했습니다.** 먼저 문구를 정의한 자리에서 한국어 리터럴로 교체했고, 그 뒤 레퍼런스 대조에서 드러난 문제 때문에 `src/copy/`로 모았습니다. 경위는 아래 "문구를 한 곳으로 모은 이유" 절에 있습니다.

1차에서는 별도 번역 테이블이나 `t()` 헬퍼를 만들지 않았습니다. KO 단일에서는 간접층이 모든 참조를 한 단계 우회시킬 뿐 얻는 것이 없고, EN을 다시 붙일 때는 언어 선택기·`localStorage` 지속·AI 프롬프트 언어까지 함께 설계해야 해서 지금 만든 구조를 어차피 다시 잡습니다. EN 재도입 시 이 교체를 들어내야 하는 비용은 감수한 결정입니다.

이미 상수로 모여 있던 문구(`EMPTY_COPY`, `ERROR_SUB`, `AUTH_ERROR_COPY`, `CARD_STATE_LABELS`, `GENERATION_ERROR_CAUSE`, `WORK_UNIT_SIGNAL_COPY`, `BLOCK_UPDATE_ERROR_CAUSE` 등)는 그 상수만 고쳤습니다. JSX 안에 직접 쓴 문장은 제자리에서 바꿨습니다.

### 서버 문구까지 옮긴 범위

화면이 `error.message`를 그대로 렌더하므로(`interview-stream-view.tsx`의 오류 박스, `repository-analysis-view.tsx`의 `StatusScreen` sub) 라우트만 빼면 한국어 화면에 영어 오류가 섞입니다. 라우트가 내려보내는 메시지의 **원천**까지 따라가 옮겼습니다.

- `app/api/**/route.ts`가 직접 쓰는 메시지
- `features/interview/llm-error.ts` — `mapInterviewLlmError`가 만드는 메시지. `${context}` 자리에 `"Question generation"`·`"Block update"` 대신 `"질문 생성"`·`"블록 갱신"`을 넘깁니다. 문구가 `이`·`에` 조사를 붙이므로 받침으로 끝나는 명사만 넘겨야 합니다
- `features/experience-candidates/schema.ts`·`candidate-client.ts` — Stage A/B 검증 실패 메시지. `repository-analysis.ts`가 `${error.message}`로 이어 붙여 화면에 그립니다
- `features/interview/question-request.ts`·`question-stream.ts`

`src/lib/github/**`의 내부 Error 메시지는 옮기지 않았습니다. 화면에 도달하지 않습니다. 화면은 `GitHubFetchError.kind`만 읽고 문구는 `errorCopy`·`ERROR_SUB`가 따로 씁니다.

`evidence-snapshot.ts`의 `EvidenceVerifiability.detail`도 옮기지 않았습니다. 화면이 아니라 `question-prompt.ts`가 AI 프롬프트에 싣는 값이고, 이슈 Constraint가 AI 프롬프트를 손대지 않는 것입니다.

## 줄바꿈

`word-break: keep-all; overflow-wrap: break-word;`를 `globals.css`의 `body`에 한 번만 뒀습니다. 두 속성 모두 상속되므로 화면마다 되풀이할 필요가 없습니다. 예전에는 `interview-stream-view.module.css`의 `.log` 하나에만 있었는데, 모든 화면이 한국어를 그리게 되어 한 자리로 올렸습니다.

mono 영역은 각 모듈에서 `word-break: normal; overflow-wrap: normal;`로 되돌립니다. 경로·SHA·코드에는 어절이 없어 어절 단위 금지가 뜻을 갖지 않고, 긴 토큰이 칸을 넘길 때는 끊어야 합니다. 되돌리는 자리는 여덟입니다.

| 모듈 | 선택자 |
| --- | --- |
| `status-screen.module.css` | `.code` |
| `app-shell.module.css` | `.repositoryMeta` |
| `code-panel.module.css` | `.collapsedFilename`, `.directoryLabel`, `.filename`, `.diffPath`, `.commitSelector code`, `.diffLineNumber`, `.diffMark`, `.diffContent` |
| `interview-stream-view.module.css` | `.message code`, `.codeBlock pre`, `.plainCode` |
| `block-sentences.module.css` | `.source` |
| `experience-candidate-detail.module.css` | `.evidenceListMeta` |
| `experience-candidate-list.module.css` | `.exclusionList code` |
| `saved-interview-screen.module.css` | `.commitBadge` |

`white-space: pre`나 `nowrap`이 걸린 자리(`.diffContent`, ellipsis를 쓰는 파일명 계열)는 애초에 줄바꿈이 일어나지 않아 두 속성이 무효입니다. 그래도 예외를 명시한 이유는 나중에 `white-space`가 바뀌어도 규칙이 남아 있게 하려는 것입니다.

## 이슈 범위 밖이었지만 함께 옮긴 것

이슈 #128의 Tasks는 저장된 인터뷰 화면을 열거하지 않았고 Non-goal은 "레퍼런스에만 있는 화면(Sessions 목록, 저장된 인터뷰 불러오기)"을 범위 밖으로 뒀습니다. 그런데 #115가 머지되면서 그 화면들이 실제 코드에 생겼습니다(`saved-interview-list.tsx`, `saved-interview-screen.tsx`). 남겨 두면 사이드바는 한국어인데 그 안의 목록은 영어인 상태가 되어, 이슈 Constraint "한 화면 안에 두 언어를 섞지 않습니다"를 정면으로 위반합니다. 함께 옮겼습니다.

Non-goal의 문장은 "레퍼런스에만 있는 화면"을 가리키는 것이고, 코드에 들어온 뒤로는 그 조건이 성립하지 않습니다.

## 남은 것

- **`aria-label="Repositories"`.** 라디오그룹의 접근성 이름이 화면의 영어 섹션 라벨 `Repositories`를 그대로 씁니다. 라벨이 영어로 남는 한 이름도 같아야 스크린리더 사용자가 보이는 것과 들리는 것을 맞출 수 있어 그대로 뒀습니다.
- **`.cardState`의 `letter-spacing`.** PAAR 카드 상태가 `수집 중`처럼 한국어인데 mono 자간 `0.05em`이 그대로 걸립니다. 디자인을 바꾸지 않는 것이 이번 Constraint라 손대지 않았습니다. 읽기 어렵다는 피드백이 나오면 그때 검토합니다.
- **EN 재도입.** 이번 작업은 KO 단일이라 `LangContext`·언어 선택기·`localStorage` 지속·브라우저 언어 감지를 만들지 않았습니다. `localization-spec.md`의 나머지 절(Language Selector, Language Persistence, Initial Language, Authentication)이 그때의 입력입니다.

영어 문구를 조회하던 테스트를 갱신했습니다. 문구 교체 자체는 회귀 테스트가 아니라 기존 테스트의 기대값 변경이므로 1차에서는 새 테스트를 만들지 않았습니다. 이후 레퍼런스 대조 누락이 드러나 `src/copy/reference-ko.test.ts`를 추가했습니다. 테스트 1,651개, lint, typecheck 통과입니다.

## 문구를 한 곳으로 모은 이유

1차 전환을 끝내고 사용자가 PAAR 카드의 `인터뷰가 아직 이 블록까지 오지 않았습니다.`를 번역체라고 지적했습니다. 고칠 문구를 찾다가 **레퍼런스에 이미 한국어 답이 있었다는 것**을 발견했습니다. `App.tsx:1382`가 같은 자리에 `notStartedYet: "아직 시작되지 않았습니다."`를 쓰고, `paar-interview-workspace.md`는 그보다 나은 voice(`현재 AI가 ~을 확인하고 있습니다`)를 예시로 싣고 있었습니다.

레퍼런스 `TRANSLATIONS.ko` 76개 항목을 전부 대조한 결과 같은 종류의 누락이 6건이었습니다.

| 자리 | 레퍼런스 | 1차 전환이 쓴 것 |
| --- | --- | --- |
| PAAR 카드 빈 상태 | 아직 시작되지 않았습니다. | 인터뷰가 아직 이 블록까지 오지 않았습니다. |
| PAAR 카드 수집 중 | 정보를 수집 중입니다... | 마지막 답변을 이 블록에 반영하고 있습니다. |
| 답변 placeholder | 질문에 답하세요... | 질문에 답해 주세요. 코드 블록을 함께 써도 좋습니다. |
| 인터뷰 종료 버튼 | 인터뷰 완료 | 인터뷰 끝내기 |
| 후보 목록 복귀 | ← 뒤로 | ← 후보 목록 |
| 저장 요약 PAAR 라벨 | PAAR 경험 | PAAR experience |

**원인은 번역 실력이 아니라 대조할 방법이 없던 것입니다.** 문구가 39개 파일에 흩어져 있어 레퍼런스 표와 나란히 놓을 수 없었습니다. 레퍼런스 표를 사전처럼 한 항목씩 찾아 쓰다 보니, 우리 쪽 영어가 더 길거나 구체적인 자리에서는 "대응 항목이 없다"고 판단하고 직접 번역했습니다. 위 여섯은 대응 항목이 **있었는데도** 그렇게 된 경우입니다.

그래서 `src/copy/`로 모았습니다. 이동 전후 실측입니다.

| | 이동 전 | 이동 후 |
| --- | --- | --- |
| 화면에 그려지는 문구를 든 파일 | 39 | 6 (`src/copy/*.ts`, 아래 `shared.ts` 추가 전 측정값. 지금은 7) |
| 화면 컴포넌트가 직접 든 문구 | 207 | 0 |
| 서버·요청 계층이 직접 든 문구(화면 도달) | 94 | 0 |
| 서로 다른 파일에 복제된 문구 | 14건 | 0 (아래 정정) |
| JSX에 직접 박힌 문장 | 약 59개 | 0 |

**복제 0건은 틀린 수치였습니다.** 셀프 리뷰에서 다시 세어 보니 `src/copy/` 안에서 파일을 넘나드는 복제가 10쌍 남아 있었습니다(`← Repository 변경`, `인터뷰 계속하기`, PAAR 빈 상태 둘 등). 화면별로 파일을 나누면서 같은 문구가 두 화면 파일에 각각 들어간 것입니다. 한쪽만 고치면 두 화면이 조용히 갈립니다. `src/copy/shared.ts`로 옮겨 한 자리에서 정의하게 고쳤습니다.

남은 중복 13건은 그대로 둡니다. **글자가 같을 뿐 뜻이 다른 경우**이고, 합치면 한쪽을 다시 쓸 때 다른 쪽이 따라옵니다. 오류 분류가 다른데 문구가 같은 것(`unknown_sha`와 `unrelated_sha`), 라우트가 다른데 문구가 같은 것, 머무르기 버튼(`CONTINUE_INTERVIEW`)과 저장본 열기 버튼(`SAVED_INTERVIEW_SCREEN_COPY.resume`)이 여기 해당합니다. 판별 기준은 `shared.ts` 머리말에 적었습니다.

이슈 #128은 "번역 테이블 도입"을 검토하고 기각했습니다. 그 판단의 근거는 **다국어 대비**였고 여전히 유효합니다. 이번에 모은 이유는 다국어가 아니라 **문구를 계속 다듬을 자리를 만드는 것**이고, 기각 사유가 다루지 않은 별개의 목적입니다. `src/copy/README.md`에 무엇을 담고 무엇을 담지 않는지 적어 두었습니다.

### 회귀를 막는 장치

`src/copy/reference-ko.test.ts`가 레퍼런스 `TRANSLATIONS.ko`의 항목을 고정하고, 항목마다 이 Repository가 **그 문구를 쓰는지** 아니면 **의도적으로 다르게 쓰는지**를 함께 기록합니다. 어긋남은 이제 둘 중 하나입니다. 표를 고치지 않은 실수이거나, 표에 사유를 적은 결정입니다.

**처음 만든 판은 짧은 문구를 잡지 못했습니다.** 모든 문구를 하나로 이어 붙인 뒤 `toContain`으로 찾는 방식이라, 두 자짜리 `취소`는 전혀 상관없는 곳에 들어 있기만 해도 통과했습니다. 실제로 취소 버튼 둘을 `그만두기`로 바꿔 보니 OAuth 오류 문구의 "권한 승인을 취소했습니다" 때문에 51개가 모두 통과했습니다. 여덟 자 이하인 항목 14개가 같은 상태였습니다.

표에 `at` 필드를 더해 그 문구를 실제로 그리는 상수를 직접 들게 하고, `at`이 있으면 `toBe`로 맞춥니다. 긴 문장은 우연히 겹칠 일이 없어 검색으로 남겼습니다. 검색에만 기대는 항목에 짧은 문구가 다시 들어오면 별도 테스트가 막습니다. 같은 실험을 다시 해서 이번에는 실패하는 것을 확인했습니다.

- 쓰는 항목 33개: 그 문자열이 `src/copy/`의 어딘가에 실제로 있는지 확인합니다.
- 다르게 쓰는 항목 18개: 그 문자열이 **없는지** 확인합니다. 누가 나중에 레퍼런스 문구로 되돌리면 테스트가 깨지고, 그때 표의 사유부터 다시 봐야 합니다.

레퍼런스 저장소는 이 저장소 밖(`Chat Interface Design`)에 있어 테스트가 직접 읽을 수 없습니다. 값을 테스트 파일에 옮겨 고정한 것은 그 때문입니다. 레퍼런스가 갱신되면 이 표도 함께 갱신해야 합니다.

### 의도적으로 레퍼런스와 다른 18건

`Repository`(→저장소 아님) 6건, `pluralCount` 영어 유지 2건, mono 상태 코드 `Authenticating`·`ERROR / AUTH` 2건, 우리 쪽이 갈래를 더 잘게 나눈 오류 안내 1건, 체크리스트 단계 구성 차이 2건, 대응 기능이 없는 항목 1건, 그리고 PAAR 카드 빈 상태 2건입니다.

마지막 둘은 레퍼런스 **구현**이 아니라 레퍼런스 **스펙**을 따른 경우입니다. `TRANSLATIONS.ko`의 `아직 시작되지 않았습니다.`는 그 자체로 상태 서술이라 이 이슈가 없애려는 문제를 그대로 갖고 있고, `paar-interview-workspace.md` 302행이 "사용자는 인터페이스만 보고도 **대화에 답하면 오른쪽 PAAR이 채워진다**는 관계를 이해할 수 있어야 합니다"라고 목표를 명시합니다. 스펙이 구현보다 정확해 스펙을 택했습니다.

## 빈 상태 문구를 쓰는 기준

이번에 세운 규칙입니다. **무엇이 아직 안 일어났는지가 아니라, 무엇을 하면 그 자리가 채워지는지를 씁니다.**

원문 구조를 그대로 두고 단어만 한국어로 바꾸면 무생물 주어와 부정 서술이 남아 번역체가 됩니다(`The interview hasn't reached this block yet.` → `인터뷰가 아직 이 블록까지 오지 않았습니다.`). 단어가 아니라 문장의 주체와 목적을 바꿔야 합니다.

본보기는 `app-shell.ts`의 `인터뷰가 없습니다. 경험 후보를 선택해 시작하세요.`입니다. 사실과 다음 행동이 한 문장씩 있습니다. 같은 기준으로 이번에 함께 고친 것은 `이 블록은 채우지 못한 채 인터뷰가 끝났습니다.`(PAAR `unfilled`), 저장 요약 화면의 안내 4개, 스트림 상태의 `아직 질문을 요청하지 않았습니다.`입니다.

사용자가 채울 수 없는 값은 예외입니다. 기술 토픽이 없는 후보처럼 사용자가 할 수 있는 일이 없으면 사실만 적습니다.

## 문구를 다듬는 기준

문구를 `src/copy/`로 모은 뒤, 6개 파일 전체를 토스의 8가지 라이팅 원칙(https://toss.tech/article/8-writing-principles-of-toss)으로 다시 읽고 고쳤습니다. 원칙의 요지는 글자 수를 줄이는 것이 아니라 의미 없는 말과 반복을 덜어내고 다음 행동을 예측할 수 있게 쓰는 것입니다.

이 Repository에 적용하면서 세운 판정 기준입니다.

| 상황 | 기준 |
| --- | --- |
| 내부 구현 용어 | 걷어냅니다. 스트림, 스냅샷, 서버 계약, 시간 예산, 색인, 출력 스키마, Stage A/B, Last-Event-ID, 요청 본문이 해당합니다 |
| 개발자가 근거를 식별하는 용어 | 남깁니다. Repository, diff, PR, patch, SHA, 커밋이 해당합니다 |
| 오류 제목과 설명 | 반복을 없앱니다. 다만 재시도 가능 여부, 보존되는 데이터, 서버 수정이 필요한지는 줄이지 않습니다 |
| 되돌릴 수 없는 조작 | 길어도 손실 범위를 남깁니다. 삭제, 화면 이탈, 인터뷰 종료가 해당합니다 |
| 오류와 빈 상태의 감정 표현 | 넣지 않습니다. 확인하지 않은 사실을 부드럽게 추측하는 것보다 원인과 다음 행동을 씁니다 |
| `aria-label`과 시각적으로 숨긴 안내 | 화면 문구와 겹쳐 보여도 삭제하지 않습니다. 같은 의미로 다듬되 접근성 정보는 보존합니다 |

내부 단계명을 사용자 흐름의 말로 옮긴 것이 가장 많습니다. `Stage A` → `1차 선별`, `Stage B` → `최종 선별`, `블록 갱신 서비스`·`질문 생성 서비스`·`LLM` → `AI`, `커밋 색인` → `불러온 커밋 목록`, `rate limit`·`호출 한도` → `요청 한도`입니다.

재시도로 풀리지 않는 서버 결함에 재시도를 권하던 문구 2건을 고쳤습니다. `config_missing`과 AI 설정 오류입니다. 사용자가 몇 번을 눌러도 같은 결과가 나오므로 서버를 고쳐야 한다고 적습니다.

이 다듬기로 레퍼런스 `TRANSLATIONS.ko`와 새로 어긋난 항목은 `reference-ko.test.ts`에 사유와 함께 추가했습니다. `connectingGitHub`, `noReposMatch`, `contributionHelper`, `loadingSavedInterviews` 4건이고, 기존 deviation 3건(`noRepoSelected`, `searchRepos`, `answerQuestion`)은 사유를 갱신했습니다.

### 문구 커밋이 테스트를 데려가지 않은 사고

토스 라이팅 원칙 적용 라운드에서 `src/copy/`만 고치고 그 문구를 조회하는 화면 테스트를 갱신하지 않은 커밋이 있었습니다. 브랜치가 3커밋 동안 red였고, 뒤 세션이 전체 테스트를 돌릴 때까지 드러나지 않았습니다. 12건을 `5ce8010`에서 한꺼번에 고쳤습니다.

원인은 화면 테스트가 문구를 문자열 리터럴로 들고 있어 `src/copy/`를 고쳐도 타입이 깨지지 않는 것입니다. `reference-ko.test.ts`는 레퍼런스와의 어긋남만 잡고 이 경우는 잡지 못합니다. 구조를 바꾸는 것은 이번 이슈 범위 밖이라 backlog로 넘겼습니다. 당분간은 `src/copy/`를 고친 커밋마다 `npm test` 전체를 돌려야 합니다.

### 중앙화가 한 파일을 통째로 옮기지 않은 사고

문구를 `src/copy/`로 모을 때 **한 파일의 message를 일부만 옮긴 자리가 넷** 남았습니다. 이슈 완료 여부를 다시 훑다가 드러났습니다.

| 위치 | 남아 있던 문구 | 분류 |
| --- | --- | --- |
| `features/interview/llm-error.ts` | `The structured response for ${context} did not match the output schema.` | `schema_validation` |
| `features/interview/sse.ts` | `Could not parse the stream data.` | `stream_interrupted` |
| `app/api/interview/stream/route.ts` | `The request body must be ${N}KB or smaller.` | `body_too_large` |
| `features/experience-candidates/llm-provider.ts` | `If NEXT_PUBLIC_LLM_BASE_URL is set, ${envName} must be set too.` | `llm_configuration` |

넷 다 화면이 `error.message`를 그대로 그리는 경로에 있습니다. `llm-error.ts`가 가장 나빴습니다. 같은 함수의 다른 갈래 12개는 전부 `LLM_ERROR_COPY`를 쓰는데 이 하나만 리터럴이었고, `context` 인자는 이미 한국어로 바뀐 뒤라 한 문장 안에서 언어가 갈렸습니다.

```
The structured response for 질문 생성 did not match the output schema.   ← 화면 1행
AI가 보낸 내용의 형식을 확인할 수 없습니다. 다시 시도하면 ...            ← 화면 2행
```

**왜 안 드러났는지가 핵심입니다.** 넷 모두 `kind`는 맞습니다. 기존 테스트가 전부 `kind`만 단정하고 `message`는 보지 않아 통과했습니다. `reference-ko.test.ts`는 레퍼런스와의 어긋남만 보므로 이 경우를 잡지 못합니다. 타입도 `string`이라 깨지지 않습니다. 즉 **세 가지 안전장치가 모두 통과하는 결함**이었습니다.

`src/copy/README.md`의 출처 목록에서도 `sse.ts`와 `llm-provider.ts`가 빠져 있었습니다. 목록을 채우고, 한 파일을 옮길 때는 그 파일이 만드는 message를 전부 세라는 문장을 README에 적었습니다.

회귀 테스트는 넷 각각에 하나씩 붙였고, `llm-error.test.ts`에는 갈래 18개를 한 번에 훑어 message에 한글이 있고 영어 문장이 섞이지 않았는지 보는 단정을 함께 뒀습니다. 갈래가 늘어도 리터럴이 남으면 여기서 걸립니다. 장치는 `schemaMismatch`를 영어로 되돌려 실제로 실패하는 것을 확인했습니다.

**남은 구조적 위험.** 같은 성격의 누락을 `sse.ts`·`route.ts`·`llm-provider.ts` 쪽에서는 여전히 갈래별 단정으로만 막습니다. 화면에 닿는 message 전체를 한 자리에서 훑는 장치는 만들지 않았습니다. 디자인 개편 backlog 33번입니다.
