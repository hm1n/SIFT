# 랜딩 화면과 검색 노출

이슈 #149가 만든 비로그인 `/`의 랜딩 화면과 검색 노출 설정의 현재 계약입니다. 로그인 진입의 상태 계약은 `wiki/2026-09-10-GitHub-로그인-진입-화면.md`에 있고, 구현 경위는 `raw/2026-09-22-랜딩-화면과-검색-노출-구현-session-log.md`에 있습니다.

확인 날짜는 2026-09-22입니다.

## 1. 화면 분기

`src/app/page.tsx`가 세션 쿠키를 읽어 가릅니다. 쿠키가 없으면 랜딩, 있으면 `RepositoryFlow`입니다. 이슈 #149는 이 분기 자체를 바꾸지 않았습니다. 쿠키가 없을 때 그리는 것이 로그인 카드에서 랜딩으로 바뀐 것이 전부입니다.

`/login` 같은 별도 경로를 만들지 않았습니다. OAuth 콜백이 돌아오는 경로와 `auth_error`·`login`·`withdrawn` 쿼리를 받는 경로, GA4 `login_view`를 보내는 자리가 모두 `/` 하나로 남아 있습니다.

세션 없는 분기의 구성은 셋입니다.

```
<AnalyticsSession … />
<UnauthenticatedScreen authError withdrawn>
  <LandingPage />
</UnauthenticatedScreen>
<SiteFooter />
```

랜딩을 `page.tsx`가 그려 `children`으로 넘깁니다. `UnauthenticatedScreen`은 인증 중 상태를 구독해야 해서 클라이언트 컴포넌트인데, 랜딩을 그 안에서 import하면 정적 마크업 약 340줄이 함께 클라이언트가 되어 JS 번들에 실립니다. 서버에서 그려 넘기면 마크업은 그대로 오고 번들은 상태 판정 코드만큼만 늘어납니다.

## 4. 제품 미리보기

스크린샷 이미지가 아니라 DOM입니다. 스펙이 실제 인터페이스를 추상 목업으로 대체하지 말라고 정했고, 이미지로 두면 해상도마다 따로 만들어야 하며 글자가 흐려집니다.

보조기술에는 한 장의 그림으로 노출합니다. 컨테이너가 `role="img"`이고 이름은 `LANDING_COPY.preview.alt` 한 문장이며 안쪽은 `aria-hidden`입니다. 안에 있는 예시 대화와 예시 코드는 제품 문구가 아니라 장면의 일부라, 읽어 주면 실제 인터뷰 내용으로 오해합니다.

상호작용 요소를 넣지 않았습니다. 버튼처럼 보이는 것도 전부 `span`입니다. 랜딩에서 누를 수 있는 것은 로그인 진입점과 약관 링크뿐입니다.

좁은 화면에서 3열을 접지 않고 가로로 스크롤합니다(`min-width: 820px` + `overflow-x: auto`). 3열이 나란한 배치 자체가 이 그림이 말하려는 것이라 열을 쌓으면 보여 줄 것이 사라집니다.

답변 입력칸의 문구와 전송 버튼은 레퍼런스 값이 아니라 실제 인터뷰 화면이 쓰는 `STREAM_VIEW_COPY`를 가져옵니다. 이 Repository는 그 자리의 문구를 이미 다르게 쓰기로 정했고(`reference-ko.test.ts`의 `answerQuestion`), 레퍼런스 값을 옮기면 랜딩에서 본 화면과 로그인한 뒤 화면의 같은 자리가 달라집니다.

## 5. 문구

한국어 문구는 레퍼런스 `TRANSLATIONS.ko`(382~410줄)를 그대로 옮겼습니다. 영어로 남는 것은 셋입니다. mono 섹션 라벨, `CODE → CHAT → PAAR` 흐름 표기, 근거 구분 태그입니다. #128이 정한 경계표를 따릅니다.

대조는 `src/copy/reference-ko.test.ts`가 합니다. 이 표는 그동안 랜딩을 담지 않았는데, 대조할 자리가 없어 결정이 아니라 미구현이었기 때문입니다. 이번에 랜딩 항목 30개를 더했습니다.

레퍼런스와 다르게 쓰는 것이 둘입니다.

- `landingFree`(`무료 · 카드 등록 불필요`)를 옮기지 않았습니다. 정해진 과금 정책이 없어 무료라고 단정할 수 없습니다(사용자 결정). 같은 이유로 `SoftwareApplication` 구조화 데이터에도 `offers`를 넣지 않았습니다.
- `footerTagline`은 법적 고지 링크가 그 자리를 씁니다. 근거는 2절과 같습니다.

## 6. 스타일

Tailwind를 도입하지 않고 CSS Modules를 유지합니다. 색과 라운드와 폰트는 `globals.css`의 CSS 변수를 씁니다. 디자인의 neutral 계열 중 토큰 자리가 없는 값(neutral-50 `#fafafa`, neutral-600 `#525252`, neutral-700 `#404040`, neutral-800 `#262626`)은 `button.module.css`·`top-header.module.css`와 같이 리터럴로 뒀습니다. 이 화면만을 위해 공용 토큰을 늘리지 않았습니다.

레퍼런스와 다르게 쓰는 것이 둘입니다. 둘 다 각 모듈 주석에 근거를 적었습니다.

**섹션 라벨의 글꼴.** 레퍼런스는 이 자리에 `font-mono`가 아니라 `font-ui`를 쓰고, KO에서 `font-ui`는 Pretendard입니다. 그래서 `.eyebrow`와 `.terms`는 `--font-sans`입니다. mono로 두면 `핵심 제품 모델`처럼 한국어가 들어오는 라벨이 Geist Mono에 한글 글리프가 없어 대체 글꼴로 떨어지고, 거기에 `0.1em` 자간까지 붙어 글자가 흩어집니다. 디자인 개편 backlog 29번이 적어 둔 문제와 같은 자리입니다. 값이 영어 라벨인 `.stepLabel`·`.columnLabel`·`.sampleTag`·`.flow`는 mono로 남습니다.

**읽어야 하는 라벨의 색.** 레퍼런스의 neutral-400은 `--color-foreground-faint`인데, `globals.css`가 흰 배경에서 대비가 약 2.5:1이라 읽어야 하는 글자에는 쓰지 않는다고 적어 둔 색입니다. 섹션 제목(`h2`) 셋과 근거 종류 태그, 그 아래 출처 줄은 읽어야 하므로 `--color-muted-foreground`(약 4.6:1)로 올렸습니다. `site-footer.module.css`가 같은 이유로 링크 색을 올렸습니다. 장식인 Hero의 큰 마크와 `01`~`04` 번호, `aria-hidden`인 흐름 표기는 원본 값 그대로입니다.

### 반응형

| 폭 | 배치 |
| --- | --- |
| 1025px 이상 | Hero 2열, 사용 흐름 4열(칸 사이 경계선), 핵심 제품 모델 3열, 근거 기반 접근 2열 |
| 641~1024px | Hero 1열(장식 마크 제거), 사용 흐름 2열, 핵심 제품 모델 1열, 근거 기반 접근 1열 |
| 640px 이하 | 좌우 여백 20px, 사용 흐름 1열, 근거 태그와 값을 위아래로 쌓음 |

제품 미리보기는 어느 폭에서도 접지 않습니다. 4절의 이유입니다.

랜딩은 뷰포트보다 길어서 `body`가 스크롤합니다. `html`이 아니라 `body`가 스크롤 컨테이너인 것은 `globals.css`가 `body`에 `height: 100%`와 `overflow-x: hidden`을 주기 때문이고, 셸을 쓰지 않는 화면의 기존 동작과 같습니다.

## 7. Loading, Empty, Error

랜딩 자체는 정적이라 데이터를 기다리는 상태가 없습니다. 세션 없는 화면의 세 상태가 그대로 대응합니다.

| 상태 | 조건 | 그리는 것 |
| --- | --- | --- |
| Empty | 기본 | 랜딩(`children`). 탈퇴 직후라면 위에 안내 한 줄 |
| Loading | 로그인 링크를 누른 뒤 브라우저가 이동하기 전 | `StatusScreen` kind `loading`, code `Authenticating` |
| Error | `auth_error`가 `AUTH_ERROR_COPY`의 키 | `StatusScreen` kind `error`, code `ERROR / AUTH`, action `다시 시도` |

인증 중 판정이 오류 판정보다 앞입니다. 헤더의 로그인 링크로 시작한 인증도 이 화면이 AUTHENTICATING으로 그려야 합니다.

## 8. 검색 노출

값은 `src/copy/shell.ts`에 모여 있습니다. 기준 도메인은 `SITE_URL`이고 `https://sift-dev.vercel.app`입니다. GitHub Repository의 homepage에 설정된 값이며 사용자가 이 값으로 정했습니다.

환경변수로 두지 않았습니다. 미리보기 배포마다 주소가 달라지는데 canonical은 어디서 열리든 정식 주소 하나를 가리켜야 합니다. 배포 환경을 따라 움직이면 미리보기 주소가 정식 주소로 색인될 수 있습니다.

### metadata

`layout.tsx`가 `DOCUMENT_COPY`를 내보냅니다. `metadataBase`가 `SITE_URL`이고 나머지 주소 필드는 상대 경로입니다.

`/privacy`와 `/terms`는 `LEGAL_PAGE_METADATA`에서 각자 canonical과 Open Graph를 받습니다. Next 16은 자식이 `openGraph`나 `alternates`를 정의하지 않으면 부모 값을 통째로 물려주므로(`node_modules/next/dist/docs/01-app/03-api-reference/04-functions/generate-metadata.md` 1418줄), 제목과 설명만 두면 두 문서를 공유했을 때 랜딩의 제목이 나가고 검색엔진이 세 주소를 모두 `/`의 사본으로 읽습니다. `src/copy/shell.test.ts`가 이 지점을 봅니다.

dev 서버에서 확인한 값입니다(2026-09-22).

| 경로 | canonical | og:title |
| --- | --- | --- |
| `/` | `https://sift-dev.vercel.app` | `SIFT \| Repository 분석` |
| `/privacy` | `https://sift-dev.vercel.app/privacy` | `개인정보 처리방침 \| SIFT` |
| `/terms` | `https://sift-dev.vercel.app/terms` | `이용약관 \| SIFT` |

세 경로 모두 `og:description`·`og:url`·`og:site_name`·`og:locale`·`og:type`과 `twitter:card`·`twitter:title`·`twitter:description`이 함께 나갑니다.

### sitemap과 robots

`src/app/sitemap.ts`와 `src/app/robots.ts`입니다. 프로덕션 빌드에서 둘 다 정적 라우트로 생성됩니다.

수집 대상은 `/`와 `/privacy`, `/terms` 셋입니다. robots는 `/api` 아래를 막습니다. 화면이 아니라 응답이고 OAuth 로그인·콜백과 세션 삭제처럼 부작용이 있는 경로가 그 아래 있습니다. 막는 것이 감추는 것은 아닙니다. robots.txt는 권한 장치가 아니라 요청이고 접근 제어는 각 라우트의 세션 검사가 합니다.

`lastModified`를 넣지 않았습니다. `new Date()`는 배포할 때마다 바뀌어 내용이 그대로인 문서까지 갱신되었다고 알립니다. 실제 갱신일을 손으로 적으면 문서를 고칠 때 같이 고쳐야 하는 자리가 하나 더 생깁니다. 세 페이지짜리 사이트에서 둘 다 값보다 비용이 큽니다.

`/`의 `<loc>`는 `SITE_URL` 그대로이고 끝에 `/`가 없습니다. Next가 만드는 canonical과 `og:url`이 끝의 `/`를 떼기 때문에 같은 화면을 가리키는 값들의 모양을 맞췄습니다. JSON-LD의 `url`도 같은 값입니다.

### 구조화 데이터

랜딩이 `WebSite`와 `SoftwareApplication`을 `@graph`로 묶어 한 번에 내보냅니다. `WebSite`는 이 주소가 무엇인지, `SoftwareApplication`은 무엇을 하는 도구인지 말합니다. 랜딩 하나가 두 역할을 겸합니다.

JSON을 넣을 때 `<`를 `<`로 바꿉니다. 값이 전부 이 저장소의 상수라 지금은 위험한 문자가 없지만, 바깥 값이 섞여도 `</script>`로 태그가 먼저 닫히지 않게 막아 둡니다. Next 문서의 권고입니다(`02-guides/json-ld.md`).

### Open Graph 이미지

`public/og-image.png`이고 주소는 `/og-image.png`입니다. 사용자가 만들어 전달했습니다. 흰 바탕에 `SiftMark`와 `SIFT` 워드마크가 있고 글자는 그 둘뿐입니다. 1730×909, 499KB입니다(확인 2026-09-22).

`src/app/opengraph-image.png` 파일 규약을 쓰지 않았습니다. 규약은 메타 태그를 자동으로 만들어 주지만 파일 위치가 `src/app` 아래로 정해지고 주소에 해시가 붙습니다. `public/`에 두면 주소가 고정돼 다른 곳에서도 같은 값으로 가리킬 수 있습니다.

그 대가로 가로·세로를 `copy/shell.ts`의 `OPEN_GRAPH_IMAGE`에 손으로 적습니다. 규약이 하던 일을 사람이 하므로 실제 파일과 어긋날 수 있고, 어긋나면 플랫폼이 잘린 카드를 그립니다. `copy/shell.test.ts`가 PNG의 IHDR을 읽어 선언한 값과 맞추고, 큰 카드로 그려지는 최소 폭 1200과 1200:630 비율도 함께 봅니다. 이미지를 바꿔 넣고 크기를 안 고치면 테스트가 잡습니다.

`twitter:image`를 명시합니다. X는 없으면 `og:image`를 대신 쓰지만 그 대체 동작에 기대지 않습니다. 비어 있으면 카드가 왜 그렇게 나오는지 태그만 보고는 알 수 없습니다.

세 화면이 같은 이미지를 씁니다. 제목과 설명은 각자 다르지만 이미지는 서비스를 가리키는 브랜드 마크 하나라 화면마다 나눌 이유가 없습니다.

### 소유권 확인

이슈 #152입니다. Search Console에 **URL 접두어** 속성으로 `https://sift-dev.vercel.app`을 등록하고 **HTML 태그** 방식으로 확인합니다. 토큰은 `shell.ts`의 `DOCUMENT_COPY.verification.google`이고 `layout.tsx`를 통해 `<meta name="google-site-verification">`으로 나갑니다.

도메인 속성을 쓸 수 없습니다. 도메인 속성은 DNS TXT 레코드를 요구하는데 `sift-dev.vercel.app`은 Vercel이 소유한 `vercel.app`의 서브도메인이라 레코드가 들어갈 `vercel.app` zone에 편집 권한이 없습니다. Vercel 대시보드에도 `*.vercel.app` 서브도메인의 DNS 레코드를 추가하는 메뉴가 없습니다. `vercel.app`은 Public Suffix List에 등재돼 있어 도메인 속성의 대상이 아닙니다.

**확인 방법마다 토큰이 다릅니다.** DNS TXT 방식은 `google-site-verification=<값>` 형태로 주고 HTML 태그 방식은 `content`의 값만 줍니다. 앞의 것을 `<meta>`에 옮겨 넣으면 확인이 실패합니다. 실제로 이 저장소도 DNS용 토큰을 먼저 받아 두고 그것을 쓰려다 방식이 다름을 확인했습니다. `shell.test.ts`가 값의 모양을 봅니다.

환경변수로 두지 않았습니다. HTML 응답에 그대로 나가는 공개 값이라 감출 것이 없고, `SITE_URL`과 같은 자리에 있어야 검색 설정이 한곳에 모입니다.

확인이 끝난 뒤에도 태그를 지우지 않습니다. 구글이 주기적으로 다시 확인하고 태그가 없으면 속성 확인이 해제됩니다.

노출 수 집계는 URL 접두어 속성으로도 도메인 속성과 같습니다. 두 속성의 차이는 집계 기능이 아니라 범위입니다. 도메인 속성은 모든 서브도메인과 프로토콜을 하나로 묶어 보여 줍니다.

검토하고 버린 방법이 셋입니다.

| 방법 | 버린 이유 |
| --- | --- |
| HTML 파일 업로드 | `public/google<해시>.html`은 파일 이름만으로 무엇에 쓰는지 알 수 없고, `shell.ts`에 모아 둔 다른 검색 설정과 떨어집니다. |
| Google 애널리틱스 연결 | gtag가 `<head>`에 있어야 하는데 `layout.tsx`의 `GoogleAnalyticsScript`는 `<body>` 끝에 있습니다(#124). |
| 자체 도메인 + 도메인 속성 | 최종 도메인을 아직 정하지 않았습니다. 도메인이 정해지면 속성을 새로 만들고 토큰도 다시 받아야 합니다. |

`/privacy`와 `/terms`에도 같은 태그가 나갑니다. Next가 자식이 정의하지 않은 필드를 물려주기 때문이고, 선언 자리는 루트 하나로 둡니다. dev 서버에서 세 경로의 응답을 읽어 확인했습니다(2026-09-22).
