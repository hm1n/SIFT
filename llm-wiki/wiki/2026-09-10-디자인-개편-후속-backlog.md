# 디자인 개편 후속 backlog

`wiki/2026-09-10-디자인-개편-계획.md`가 이번 개편에서 하지 않기로 한 항목과, 하위 이슈를 구현하며 후속으로 분리한 항목을 모읍니다. 새 GitHub 이슈를 만들지 않고 여기에 적습니다.

확인 날짜는 2026-09-11입니다.

## 개편 범위 밖으로 둔 항목

1. **코드 패널의 FILE 모드.** 디자인은 코드 패널에서 DIFF와 FILE 두 모드를 전환합니다. 근거 스냅샷에는 변경 patch만 있고 파일 전체 원문이 없어 API 확장이 먼저 필요합니다. #98은 DIFF 모드만 구현합니다.
2. **사이드바 인터뷰 세션 목록.** 디자인은 사이드바 Interviews 영역에 진행 중이거나 끝난 인터뷰를 나열합니다. 세션 저장 계층이 없어 나열할 데이터가 없습니다. #93은 빈 상태 문구만 둡니다. 세션 저장은 `wiki/2026-08-24-경험선택-세션저장-후속-backlog.md`와 같은 항목입니다.
3. **계정 삭제.** 디자인의 계정 메뉴에 `Delete account`가 있습니다. MVP 범위 밖이고 삭제할 서버 저장 데이터도 없습니다. 계정 메뉴는 `Sign out`만 둡니다.
4. **질문이 참조한 파일만 골라 표시하는 기능.** 디자인은 질문 메시지에 참조 파일 칩을 붙이고 누르면 코드 패널이 그 파일로 이동합니다. 질문 스트림 계약에 참조 파일 정보가 없어 구현할 수 없습니다. 스트림 계약 변경은 인터뷰 질문 생성 쪽 작업입니다.
5. **PAAR 패널의 시각 반영.** #89~#91이 블록 계약을 만든 뒤 그 위에 얹습니다. #98은 오른쪽 열의 자리와 폭만 잡습니다.
6. **다크 테마.** 디자인 파일에 다크 테마가 없습니다. 토큰을 CSS 변수로 두므로 나중에 추가할 수 있지만 지금 만들지 않습니다.

## #93에서 분리한 항목

7. **Pretendard 자체 호스팅.** #93은 디자인 파일과 같은 jsDelivr CDN CSS를 씁니다. 외부 요청 한 건이 추가되고 CDN이 막힌 환경에서는 시스템 폰트로 대체됩니다. #95에서 실측한 결과 현재 CSS는 2,057,688바이트 woff2 하나를 받고 응답 완료가 108~135ms였습니다. 자체 호스팅은 하지 않기로 했습니다. 같은 CDN의 동적 서브셋 CSS(`pretendardvariable-dynamic-subset.css`)는 선택 화면에서 woff2 7개 183,696바이트, 59~77ms로 전송량이 91% 줄었습니다. `layout.tsx`의 URL 한 줄과 `wiki/2026-09-10-디자인-토큰과-공통-셸.md` 폰트 등록 절을 함께 고치는 후속으로 남깁니다. 실측 경위는 `raw/2026-09-11-Repository-목록-조회와-선택-화면-구현-session-log.md` 4절입니다.
8. **TopHeader의 사용자명과 이니셜.** 세션 쿠키에 GitHub 사용자 정보가 없어 #93은 로그인 여부만 그립니다. #94에서 정했습니다. #94 Constraint가 세션 쿠키 계약을 바꾸지 않는 것이라 쿠키에 사용자 정보를 넣을 수 없고, 남는 방법은 layout에서 매 요청 GitHub `/user`를 조회하는 것인데 모든 페이지에 왕복 한 번이 붙습니다. #94에서는 넣지 않았습니다. #95에서 판단한 결과 목록 API에 묶는 방법은 쓸 수 없습니다. 목록은 클라이언트가 렌더 뒤에 가져오고 `TopHeader`는 layout 서버 컴포넌트가 그리므로 목록 응답에 `/user`를 실어도 헤더에 닿지 않습니다. 남는 선택지는 쿠키 계약 변경이나 layout의 `/user` 조회 둘이고, 디자인 개편 안에서는 넣지 않습니다.

## #95에서 분리한 항목

9. **기여 문장을 항목으로 풀어내기.** 선택 화면의 textarea는 디자인대로 한 문장 placeholder를 쓰지만 항목 경계는 줄바꿈이라 한 문장이 항목 하나가 됩니다. Stage A의 `contributionItem` 대조는 입력 집합과 정확히 일치해야 하므로 문장 하나로는 분류가 거칠어집니다. 쉼표·마침표 분리는 어색한 조각을 만들어 접었습니다. Stage A 프롬프트가 문장을 항목으로 풀어 돌려주게 하거나 대조를 완화하는 일은 Stage A 쪽 작업입니다.
10. **목록 페이지네이션의 누락.** `/user/repos`의 커서는 page 번호라서 조회 도중 목록이 바뀌면 경계에서 항목이 빠질 수 있습니다. 중복은 `id`로 걸러내지만 누락은 남습니다. GraphQL의 커서나 조회 뒤 개수 대조 같은 방법은 실제 누락이 관찰되면 검토합니다.
11. **되돌아갈 때 선택 보존.** 분석 화면에서 "다른 Repository 선택"으로 돌아오면 목록을 다시 조회하고 이전 선택과 기여 입력을 보존하지 않습니다. 디자인 `handleChangeRepo`와 같은 동작이지만, 기여 문장을 길게 쓴 뒤 Repository를 바꾸는 사용자는 다시 써야 합니다. 보존이 필요하다는 피드백이 있으면 흐름 컴포넌트의 상태로 올립니다.
12. **archived·fork 표시와 필터.** 목록 응답에 archived와 fork 여부를 싣지 않고 화면에도 표시하지 않습니다. 이슈 Non-goal의 Organization 전환·필터와 같은 묶음입니다.
13. ~~**비공개 Repository 접근 scope.**~~ 해결되었습니다. PR #73은 OAuth scope를 `read:user` 하나로 정해 비공개 Repository를 지원하지 않았습니다. PR #102 Codex 리뷰가 P1로 지적했고, 사용자가 `repo` scope 요구를 선택해 PR #102에서 scope를 `read:user repo`로 넓혔습니다. `repo`는 OAuth App이 비공개 Repository를 읽을 수 있는 유일한 scope이고 쓰기 권한도 함께 줍니다. 경위는 `raw/2026-09-11-OAuth-repo-scope-결정-session-log.md`에 있습니다.
