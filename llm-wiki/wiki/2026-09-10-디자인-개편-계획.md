# 디자인 개편 계획

Figma Make로 완성한 서비스 디자인을 기준으로 전체 UI를 개편하는 작업의 계획과 공통 결정을 담습니다. 상위 이슈는 #92이고 하위 이슈는 #93부터 #98까지 여섯 개입니다. 계획을 세운 세션의 경위는 `raw/2026-09-10-디자인-개편-계획-session-log.md`에 있습니다.

확인 날짜는 2026-09-10입니다.

## 1. 디자인 원본

- 경로는 `C:\Users\user\Desktop\Chat Interface Design`입니다. 저장소 밖에 있고 사용자가 계속 수정합니다. 작업 전 파일 갱신 시각을 확인합니다.
- `src/App.tsx`는 Tailwind v4 유틸리티와 하드코딩 목업 데이터로 쓴 화면 원본입니다. `src/index.css`의 `@theme` 블록이 토큰 원본입니다.
- 스펙 문서는 `src/imports/pasted_text/` 아래 다섯 개입니다. `product-flow-update.md`, `interview-workspace-spec.md`, `paar-interview-workspace.md`, `multi-file-evidence-nav.md`, `contribution-context.md`입니다. 마지막 문서는 2026-09-10 16:35 갱신본에서 추가되었습니다.

### 화면 흐름

GitHub 로그인, Repository 목록 선택, 분석 진행, 경험 후보 master-detail, 인터뷰 3열 워크스페이스 순서입니다. 인터뷰 3열은 왼쪽 CODE, 가운데 CHAT, 오른쪽 PAAR입니다.

### 시각 언어

- monochrome이고 1px border를 씁니다. 그림자와 그라디언트를 쓰지 않습니다.
- 본문은 소문자 문장이고 메타데이터는 대문자 mono 라벨입니다. 라벨 크기는 9px, 10px, 11px이고 letter-spacing을 넓게 둡니다.
- radius는 7px입니다.
- 폰트는 Inter(본문), Geist Mono(코드와 라벨), Pretendard(한국어 자연어 입력과 안내)입니다.

## 2. 공통 결정

| 항목 | 결정 | 근거 |
| --- | --- | --- |
| 스타일 기반 | Tailwind를 도입하지 않습니다. CSS Modules를 유지하고 디자인 토큰은 `globals.css`의 CSS 변수로 옮깁니다. | 기존 모듈 파일 8개와 화면 테스트가 CSS Modules 기반입니다. 디자인의 유틸리티 클래스는 어차피 다시 써야 합니다. |
| 문구 언어 | 디자인대로 영어를 씁니다. 사용자가 한국어로 입력하는 영역의 안내와 placeholder는 디자인이 한국어로 둔 곳만 한국어입니다. | #92 공통 결정입니다. |
| PAAR 두 번째 블록 라벨 | 디자인의 `ANALYZE`를 씁니다. | 이 결정은 PAAR 설계 위키의 `ALTERNATIVE`를 대체합니다. 그 위키와 #89~#91의 키 이름 갱신은 PAAR 설계 세션이 담당하며 이 문서의 범위가 아닙니다. |
| 기여 항목 입력 위치 | Repository 선택 화면에서 Repository 목록 카드 아래에 별도 섹션으로 둡니다. 라벨은 `YOUR CONTRIBUTION`과 `OPTIONAL`이고 안내와 placeholder는 한국어 Pretendard입니다. 목록과 섹션은 같은 600px 열을 공유하고 사이 간격은 20~24px입니다. textarea는 3행에서 시작해 160px까지 자동 확장합니다. | 2026-09-10 16:35 갱신본의 `contribution-context.md`와 `App.tsx`의 `RepoSelectScreen`으로 확정했습니다. 구현은 #95입니다. |

기여 항목 입력값은 검증된 Repository 근거가 아니라 사용자 제공 힌트입니다. 분석에서 우선순위를 정하는 데 쓰되 실제 커밋과 파일로 확인한 것만 근거로 표시합니다. 이 원칙은 `AGENTS.md`의 근거 구분 원칙과 같습니다.

## 3. 하위 이슈와 순서

1. #93 디자인 토큰과 공통 셸 도입
2. #94 GitHub 로그인 진입 화면과 인증 상태
3. #95 Repository 목록 조회와 선택 화면. `GET /api/github/repositories` 라우트를 새로 만듭니다.
4. #96 Repository 분석 진행 화면 개편
5. #97 경험 후보 master-detail 화면 개편

하위 이슈 하나를 PR 하나로 구현합니다.

### #93의 범위 결정

- Pretendard는 Google Fonts에 없으므로 `next/font/google`로 등록할 수 없습니다. 디자인 파일과 같은 jsDelivr CDN CSS를 `layout.tsx`의 `<link>`로 넣습니다. 자체 호스팅은 #95에서 실측한 뒤 하지 않기로 했습니다. 동적 서브셋 전환은 `wiki/2026-09-10-디자인-개편-후속-backlog.md` 7번입니다.
- 세션 쿠키에는 암호화한 토큰만 있고 GitHub 사용자 정보가 없습니다. #93의 `TopHeader`는 로그인 전의 `Log in with GitHub`와 로그인 후의 `Sign out` 두 상태만 그립니다. 사용자명과 이니셜 표시는 #94에서 #95로 넘겼고 #95에서 넣지 않기로 했습니다. 경위는 `wiki/2026-09-10-디자인-개편-후속-backlog.md` 8번에 있습니다.
- 현재 진입 화면에는 Repository 선택 개념이 없어 사이드바에 그릴 정보가 없습니다. #93은 `AppShell` 컴포넌트와 테스트만 만들고 실제 배치는 #96 이후 화면 이슈가 합니다.

### #95의 범위 결정

- 기여 항목의 경계는 줄바꿈 규칙을 유지합니다. 문장을 항목으로 풀어내는 일은 Stage A 쪽 후속입니다.
- rate limit이 아닌 403은 새 오류 종류를 만들지 않고 `auth_revoked`로 둡니다. 목록 조회 라우트의 계약은 `wiki/2026-09-11-Repository-목록-조회와-선택-화면.md`에 있습니다.
- `RepositoryAnalysisView`는 입력 폼을 잃고 선택 화면이 넘기는 prop으로 시작합니다. 결과 영역의 스타일 재배치는 #96입니다.

### #96의 범위 결정

- Loading은 `StatusScreen`을 쓰지 않고 전용 컴포넌트(`LoadingChecklist`)로 뺍니다. 디자인의 `AnalyzingScreen`과 `StatusScreen`이 원래 서로 다른 컴포넌트였기 때문입니다. Empty·Error는 `StatusScreen`을 그대로 재사용합니다.
- `StageAExclusions`는 `StatusScreen`의 `sub`가 아니라 형제 엘리먼트로 그립니다. `StatusScreen`의 계약은 바꾸지 않습니다.
- 영어 번역은 GitHub 조회 오류 5종(+ `partial_failure`)과 Empty 5종만 합니다. 후보 생성 오류(LLM·diff 재조회·Stage A/B)의 번역은 `wiki/2026-09-10-디자인-개편-후속-backlog.md` 16번으로 분리했습니다.
- `AppShell`을 분석 화면에 처음 실제로 배치합니다. 상세 계약은 `wiki/2026-09-11-Repository-분석-진행-화면-개편.md`에 있습니다.

## 5. 기존 이슈와의 충돌

#91은 "근거 패널을 옮기지 않습니다"를 Constraint로 두고 블록 패널을 근거 패널과 함께 배치합니다. 새 디자인은 근거 패널을 왼쪽 열로 옮기고 PAAR을 오른쪽 열에 둡니다. #98이 배치를 바꾸므로 #91의 배치 관련 Constraint와 Approach 1은 그에 맞춰 고쳐야 합니다. #91 수정은 사용자 승인 전까지 하지 않습니다.

## 6. 유지하는 제약

- `InterviewStreamView`의 렌더링 방식, 자동 스크롤, 낭독 경계를 바꾸지 않습니다. 이슈 #60 실측으로 확정된 부분입니다.
- 근거의 확인 가능 여부 표시(VERIFIED FROM REPOSITORY와 사용자 진술 구분)를 어느 화면에서도 없애지 않습니다.
- Loading, Empty, Error 상태를 모든 화면에서 함께 구현합니다.
- 색으로만 상태를 구분하지 않습니다. 기호와 라벨을 함께 씁니다.
- 최적화는 실측 근거가 있을 때만 적용합니다.
