# 경험 후보 출력 검증 후속 backlog

## 문서 목적

Issue #15 PR(#24) 재검증 리뷰에서 non-blocking으로 판정해 이번 PR에 반영하지 않은 항목을 기록합니다. 별도 GitHub Issue는 만들지 않습니다.

## 미뤄 둔 항목

### 1. 인용 파일 경로에서 디렉터리 제외

`assertCandidateEvidence`가 Repository 파일 트리의 `path`만 받아 인용 경로와 대조하므로, `type: "tree"`인 디렉터리도 파일 근거처럼 통과할 수 있습니다.

Codex 재검증 리뷰는 이 문제를 P2로 분류했습니다. 재검증에서 새로 발견된 P2/P3는 backlog로 옮기고 리뷰 라운드를 늘리지 않는 코드 리뷰 전략에 따라 이번 PR에서는 수정하지 않습니다. 실제 파일이 아닌 경로가 근거로 표시될 수 있지만 SHA와 PR 관계는 검증된 상태이고, 수정하려면 `ExperienceCandidateEvidenceInput.fileTree`가 `type`을 보존하도록 계약과 테스트를 함께 바꿔야 합니다.

후속 작업에서는 `RepositoryTreeEntry`의 `path`와 `type`을 함께 받고 `blob` 항목만 인용 가능한 파일 트리에 포함합니다. 디렉터리 경로가 `unknown_file_path`로 거부되는 회귀 테스트를 추가합니다.

### 2. 부족 사유 검증식 축약

이슈 #108에서 부족 사유 규칙을 후보 0개에만 묶으면서 `validateExperienceCandidateOutput`의 `reasonIsValid`가 삼항 두 갈래로 늘어났습니다. 다음 한 줄과 같은 뜻입니다.

```ts
const reasonIsValid = isNonEmptyString(reason) || (value.candidates.length > 0 && reason === null);
```

자체 리뷰에서 P3으로 판정했습니다. 동작이 같고 테스트가 양쪽 갈래를 모두 덮고 있어 이번 PR에서는 바꾸지 않았습니다. 확인 날짜는 2026-09-11입니다.

### 3. 부족 사유 화면 문구와 정리 사유의 어긋남

`experience-candidate-list.tsx`는 `insufficientCandidatesReason`을 `후보를 더 채우지 않은 이유`라는 제목으로 보여줍니다. 그런데 `dedupeCandidatesByWorkUnit`이 같은 Pull Request 후보를 합쳤을 때 채우는 사유는 "합쳐서 N개가 되었다"는 설명이라 제목과 뜻이 어긋납니다. 후보를 상한만큼 골랐는데도 이 사유가 붙을 수 있습니다.

자체 리뷰에서 P3으로 판정했습니다. 고치려면 사유를 "덜 고른 이유"와 "정리한 결과" 두 종류로 나눠 타입과 화면을 함께 바꿔야 하므로 이번 PR 범위 밖입니다. `types.ts`의 `insufficientCandidatesReason` 주석이 이 겹침을 적어 두고 있습니다. 확인 날짜는 2026-09-11입니다.
