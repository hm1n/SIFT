# 운영 준비 체크리스트

## 문서 목적

실사용자에게 서비스를 여는 데 필요한데 아직 없는 것을 한곳에 모읍니다. 기능 구현은 끝났고 테스트도 통과하지만, 서비스를 계속 굴리는 데 필요한 층이 비어 있습니다. 그 층을 등급으로 나눠 적습니다.

항목이 닫히면 이 문서의 해당 절을 갱신합니다. 이미 다른 backlog 문서에 있는 항목은 그 문서를 근거로 걸고 여기서는 운영 관점의 등급만 다시 매깁니다.

P0은 2026-09-18에 GitHub Issue로 옮겼습니다. 각 절에 이슈 번호를 답니다. P1과 P2는 이슈를 만들지 않고 이 문서에 둡니다.

## 등급 기준

- **P0**은 실사용자에게 공개하기 전에 닫아야 합니다. 법적 고지, 비용 방어, 회귀 방어, 장애 추적처럼 없으면 공개 자체가 위험한 항목입니다.
- **P1**은 공개한 뒤 초기 운영 중에 닫습니다. 사용자가 늘수록 문제가 커지는 항목입니다.
- **P2**는 여유가 생길 때 처리합니다.

이 등급은 `AGENTS.md`의 코드 리뷰 등급과 뜻이 다릅니다. 저기는 한 PR을 머지할 수 있는지의 기준이고, 여기는 서비스를 열 수 있는지의 기준입니다.

## 2026-09-18 기준 현재 상태

- `v0.1.0` 태그로 프로덕션 배포가 한 번 나갔습니다. 그 뒤 **develop이 main보다 29커밋 앞서 있습니다.** 지금 프로덕션에 떠 있는 코드는 그만큼 예전 것입니다.
- 테스트는 106개 파일 1,967건이 모두 통과합니다.
- 이 문서를 쓰기 전에는 열려 있는 GitHub Issue가 없었습니다. P0 다섯 건을 같은 날 이슈 #141부터 #145로 만들었고, P1과 P2는 아직 이슈가 없습니다.

## P0

### 1. 개인정보 처리방침과 이용약관이 없습니다 (#141, 해결)

2026-09-18에 두 화면을 만들고 고충 처리 창구의 연락처까지 채웠습니다. 구성과 근거 대조표는 `wiki/2026-09-18-법적-고지-문서.md`에 있습니다.

남은 것은 이 항목을 막지 않습니다. 수탁자 연락처 주소 네 개의 확인, 이용약관의 법률 검토, #145가 들어온 뒤 권리 행사 방법을 화면 경로로 고치는 일입니다. 같은 문서의 마지막 절에 적었습니다.

아래는 항목을 연 시점의 기록입니다.

`wiki/2026-09-15-GA4-계측-후속-backlog.md` 1번이 같은 사실을 적고 "운영을 시작하기 전에는 닫혀야 하는 항목"이라고 판정했습니다. 그 판정을 그대로 잇습니다.

- 로그인 화면에 "계속하면 이용약관에 동의하는 것입니다"라는 문구가 있고 링크가 없습니다. `src/copy/auth.ts:17`과 `src/features/auth/login-screen.tsx:83`입니다. 존재하지 않는 문서에 동의를 받고 있습니다.
- 처리방침 화면도 라우트도 없습니다. `src/app` 아래에는 `page.tsx`와 `api/`뿐입니다.

적어야 할 항목이 GA4 하나가 아닙니다. 네 가지를 함께 적어야 의미가 있습니다.

- GitHub OAuth 토큰을 암호화해 쿠키에 담습니다. `src/lib/github/auth-session.ts`입니다.
- OAuth scope가 `read:user repo`라 비공개 Repository까지 읽습니다. `src/lib/github/oauth.ts:43`입니다.
- `github_user_id`와 근거 스냅샷을 Neon에 저장합니다. `db/schema.sql`입니다.
- 커밋과 diff를 Google Gemini로 보냅니다. `src/features/experience-candidates/llm-provider.ts`입니다.

### 2. 비용을 막을 수단이 한 겹도 없습니다 (#142)

사용자나 IP 단위로 요청 수를 제한하는 코드가 없습니다. 저장소 전체에서 `rateLimit`과 `quota` 계열 문자열이 걸리는 파일은 모두 GitHub과 LLM 제공자가 서비스 쪽에 돌려주는 429를 처리하는 코드입니다. 서비스가 사용자에게 거는 제한은 없습니다.

`wiki/2026-09-02-LLM-비용-산정.md` 기준으로 분석 한 번이 0.02182달러이고 저장소가 커도 0.03833달러를 넘지 않습니다. 여기에 인터뷰 턴마다 블록 갱신 호출이 더 붙습니다. GitHub 계정만 있으면 같은 저장소를 몇 번이든 다시 분석할 수 있습니다.

사용자당 하루 분석 횟수 상한이 가장 작은 비용으로 막을 수 있는 자리입니다.

### 3. PR에서 테스트와 typecheck가 돌지 않습니다 (#143)

`.github/workflows`에 `create-release-note.yml` 하나뿐입니다. 배포 성공 이벤트를 받아 태그와 GitHub Release를 만드는 워크플로이고, 코드를 검사하는 워크플로가 없습니다.

지금까지는 사람이 매번 직접 돌려서 막았습니다. 실사용자가 있는 상태에서는 회귀 하나가 그대로 프로덕션으로 갑니다. 테스트 1,967건이 이미 있으므로 워크플로 하나를 더하는 비용 대비 효과가 이 목록에서 가장 큽니다.

### 4. Sentry가 오류를 받아도 원인을 찾을 수 없습니다 (#144, 코드 반영 완료)

`next.config.ts`가 `sourcemaps: { disable: true }`와 `release: { create: false }`로 둘을 명시적으로 끕니다. 이슈 #81이 Releases와 Source Map 업로드를 범위 밖으로 둔 결정이고 그 시점에는 맞았습니다.

실사용자 오류가 들어오기 시작하면 상황이 달라집니다. 스택 프레임이 난독화된 번들 기준이라 어느 코드인지 알 수 없고, release 값이 없어 어느 배포에서 난 오류인지도 구분되지 않습니다. 첫 장애에서 바로 걸립니다.

**2026-09-18에 두 옵션을 켰습니다.** 클라이언트와 서버 소스맵이 Sentry로 올라가고 브라우저에는 남지 않으며, 커밋 SHA가 release로 모든 이벤트에 붙습니다. 설정과 실측은 `wiki/2026-09-18-sentry-source-map-release.md`에 있습니다. 남은 것은 콘솔 작업입니다. Sentry auth token을 발급해 Vercel의 `SENTRY_AUTH_TOKEN`에 넣어야 업로드가 실제로 일어나고, 그 뒤 프로덕션 오류 한 건으로 스택과 release를 확인해야 이 항목이 닫힙니다.

### 5. 계정 데이터를 지울 방법이 없습니다 (#145, 해결)

2026-09-18에 계정 메뉴의 회원 탈퇴로 닫았습니다. 계약과 근거는 `wiki/2026-09-18-회원-탈퇴와-연결-해제.md`에 있습니다. `DELETE /api/account`가 세션의 사용자 번호로 그 사용자의 분석과 인터뷰를 모두 지우고, GitHub OAuth grant를 해제하고, 세션 쿠키를 지웁니다. 해제가 실패해도 삭제는 끝나며 그 사실을 로그인 화면이 알립니다. 처리방침 8번과 이용약관 2번에 그 경로를 적었습니다.

남은 것은 이 항목을 막지 않습니다. 로그아웃은 여전히 토큰을 무효로 만들지 않고(쿠키가 사라진 뒤에도 발급 후 8시간 안에서는 토큰이 살아 있습니다), 권한 해제 실패가 Sentry로 가지 않습니다. 같은 문서의 마지막 절에 적었습니다.

아래는 항목을 연 시점의 기록입니다.

인터뷰 한 건을 지우는 경로와 90일 미열람 자동 정리는 있습니다. `DELETE /api/interviews/[id]`와 `src/app/api/cron/purge/route.ts`입니다.

없는 것은 계정 단위의 전체 삭제입니다. 로그아웃은 쿠키만 지우고 GitHub 토큰을 revoke하지 않습니다. `src/app/api/auth/session/route.ts`입니다. 1번의 처리방침을 쓰려면 삭제를 요구하는 방법을 함께 적어야 하는데 지금은 적을 것이 없습니다.

### 6. 요금과 사용량 알림이 걸려 있는지 모릅니다 (확인 필요) (#142에 포함)

Google AI Studio의 예산 알림, Neon과 Vercel의 사용량 알림이 설정돼 있는지는 외부 콘솔 설정이라 코드로 확인할 수 없었습니다. 2번의 상한과 짝이 되는 항목이므로 함께 확인합니다.
