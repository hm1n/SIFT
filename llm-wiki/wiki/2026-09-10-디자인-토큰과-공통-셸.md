### 폰트 등록

- Inter와 Geist Mono는 `layout.tsx`에서 `next/font/google`로 등록하고 CSS 변수 `--font-inter`, `--font-geist-mono`로 노출합니다. 자체 호스팅이므로 외부 요청이 없습니다.
- Pretendard는 Google Fonts에 없어 jsDelivr CDN 스타일시트를 `<link>`로 넣습니다. 자체 호스팅 여부는 `wiki/2026-09-10-디자인-개편-후속-backlog.md` 7번입니다.

### 한글은 `--font-sans`가 담당합니다 (2026-09-14 갱신)

처음에는 `--font-sans`가 `var(--font-inter), ui-sans-serif, system-ui, -apple-system, sans-serif`였고 Pretendard를 참조하는 곳은
`repository-select-screen.module.css`의 `.contributionCopy`와 `.textarea` 둘뿐이었습니다. 나머지 화면의 한글은 Pretendard를
거치지 않고 OS 기본 한글 폰트로 떨어졌습니다. Windows는 맑은 고딕, macOS는 Apple SD Gothic Neo라 화면이 환경마다 달랐습니다.
인터뷰 채팅은 자기 `font-family`가 없어 그대로 이 경로를 탔습니다.

그래서 `--font-sans`에 Inter 다음 자리로 Pretendard를 넣었습니다.

```
--font-sans: var(--font-inter), "Pretendard Variable", "Pretendard", ui-sans-serif, system-ui, -apple-system, sans-serif;
```

화면 모듈마다 한글 폰트를 지정하지 않아도 되는 근거는 대체가 글자 단위로 일어나기 때문입니다. 빌드된 CSS에서 확인한 사실 둘입니다.

- `--font-inter`는 `"Inter", "Inter Fallback"` 두 개로 펼쳐지고, `Inter Fallback`은 `src: local(Arial)`입니다.
- Inter의 `@font-face`에 등록된 `unicode-range`는 라틴·라틴 확장·키릴·그리스·베트남어뿐이고 한글 범위 `U+AC00-D7A3`이 없습니다.

따라서 한글은 Inter와 Arial을 모두 지나쳐 Pretendard에서 처음 멈추고, 영문·숫자·문장부호는 라틴 서브셋의 `U+00-FF`에 들어가
Inter에서 멈춥니다. `--font-mono`는 건드리지 않았으므로 라벨과 diff와 파일명은 Geist Mono 그대로입니다.

`--font-pretendard`는 지우지 않았습니다. 영문까지 Pretendard로 그려야 하는 자리가 위 두 곳에 남아 있습니다. 다만 그 두 곳만
영문 폰트가 다른 화면과 다르다는 뜻이므로, 의도한 것인지 확인이 필요합니다.

## 2. 셸 컴포넌트

`src/components/shell/`에 있고 파일마다 직접 import합니다. 배럴 파일은 두지 않습니다.

| 컴포넌트 | 역할 | 계약 |
| --- | --- | --- |
| `TopHeader` | 모든 화면 위의 44px 헤더 | `isAuthenticated`가 false면 `LoginLink`(`Log in with GitHub`), true면 `AccountMenu`를 그립니다. 로그인 링크는 로그인 화면 버튼과 인증 중 상태를 공유하므로 `AuthTransitionProvider` 안에서만 그릴 수 있습니다. 사용자명은 세션에 없어 그리지 않습니다. #95에서 목록 API에 묶는 방법이 헤더에 닿지 않음을 확인해 디자인 개편 안에서는 넣지 않기로 했습니다(`wiki/2026-09-10-디자인-개편-후속-backlog.md` 8번). |
| `AccountMenu` | 로그인 뒤 계정 메뉴 | 항목은 `Sign out` 하나입니다. 세션 삭제 라우트를 `DELETE`로 부른 뒤 첫 화면으로 이동하고 서버 컴포넌트를 다시 그립니다. 삭제 요청이 실패해도 이동하며, 쿠키가 남아 헤더가 그대로면 메뉴가 닫히고 다시 누를 수 있습니다. Escape와 바깥 클릭으로 닫힙니다. |

| `Button`, `ButtonLink` | 버튼 3종 | `variant`는 `primary`(검정 배경), `secondary`(1px border), `ghost`(텍스트)입니다. 크기 변형은 쓰는 화면이 생길 때 더합니다. |
| `SiftMark`, `GitHubIcon` | 로고와 GitHub 마크 | 디자인 파일의 SVG를 그대로 옮겼고 `currentColor`를 따릅니다. |

## 3. 적용 범위

- `layout.tsx`가 세션 쿠키 유무를 읽어 `TopHeader`를 그립니다. 그래서 layout은 동적으로 렌더됩니다. 첫 화면 page가 이미 쿠키를 읽고 있어 새로 생기는 비용은 없습니다.
- 세션 여부의 출처는 서버가 읽는 세션 쿠키 하나입니다. #94부터 `page.tsx`가 쿠키 유무로 `LoginScreen`과 로그인 뒤 흐름을 가르고, #95부터 그 흐름은 `RepositoryFlow`(선택 화면과 분석 화면)입니다. 화면은 로컬 세션 상태를 두지 않습니다. 로그인 화면 계약은 `wiki/2026-09-10-GitHub-로그인-진입-화면.md`에 있습니다. 로그아웃 진입점은 헤더의 Sign out과 오류 안내의 다시 로그인 둘이고, 둘 다 세션 삭제 뒤 라우터를 갱신해 서버가 헤더와 화면을 함께 다시 그립니다. 서버가 다시 그리면 흐름이 통째로 내려가 상태가 사라지고, 진행 중이던 요청이 늦게 보내는 결과는 언마운트와 실행 번호로 막습니다. #95에서 `hasSession` prop을 지웠습니다. 경위는 `raw/2026-09-10-디자인-토큰과-공통-셸-리뷰-1차-session-log.md`에 있습니다.
- 로그인 전 진입 화면은 #94가, 로그인 뒤 첫 화면인 Repository 선택은 #95가 디자인대로 만들었습니다. 분석 결과 영역의 색과 카드 모양은 그대로이고 재배치는 #96이 합니다. 옛 `page.module.css`의 배치는 `features/repository-selection/repository-flow.module.css`로 옮겼습니다.

## 5. 확인 필요

- Pretendard CDN이 막힌 환경에서 시스템 폰트로 대체되는지는 보지 않았습니다. `--font-sans`가 한글을 담당하게 된 뒤로는 막혔을 때
  전 화면의 한글이 OS 기본 폰트로 돌아갑니다. 영향 범위가 두 요소에서 전 화면으로 넓어졌습니다.
- `.contributionCopy`와 `.textarea`가 `--font-pretendard`를 써서 영문까지 Pretendard로 그리는 것이 의도한 차이인지 확인하지 못했습니다.
- `StatusScreen`은 #94의 로그인 화면이 AUTHENTICATING과 ERROR / AUTH로 처음 배치했고 #95의 선택 화면이 LOADING REPOSITORIES, NO REPOSITORIES, ERROR / GITHUB로 씁니다. `AppShell`은 아직 어느 화면도 쓰지 않습니다.
