# GitHub 로그인 진입 화면

이슈 #94가 만든 로그인 진입 화면과 인증 상태의 현재 계약입니다. 배경은 `wiki/2026-09-10-디자인-개편-계획.md`에, 구현 경위는 `raw/2026-09-10-GitHub-로그인-진입-화면-구현-session-log.md`에 있습니다.

확인 날짜는 2026-09-10입니다.

## 1. 화면 분기

`src/app/page.tsx`가 세션 쿠키를 읽어 가릅니다. 쿠키가 없으면 `LoginScreen`, 있으면 `RepositoryAnalysisView`입니다. 세션 여부의 출처는 이 쿠키 하나이고 로그인 화면은 인증 상태를 들고 있지 않습니다. 세션이 있으면 `auth_error` 쿼리를 무시합니다.

로그아웃은 세션 삭제 뒤 `router.refresh()`로 이 페이지를 다시 실행시키는 방식이라, 서버가 `RepositoryAnalysisView`를 `LoginScreen`으로 바꿔 그립니다. `RepositoryAnalysisView`의 `hasSession` prop과 상태 초기화는 PR #99 리뷰 결정대로 남겨 두었습니다.

## 2. LoginScreen

`src/features/auth/login-screen.tsx`입니다. prop은 `authError?` 하나이고 `page.tsx`가 `searchParams.auth_error`의 첫 값을 넘깁니다.

| 상태 | 조건 | 그리는 것 |
| --- | --- | --- |
| Empty | 기본 | 80px dashed 상자 안 `SiftMark` 40, 제목 "Turn your code into experiences worth talking about.", 설명, primary `ButtonLink` "Continue with GitHub", mono 약관 문구. dashed 상자는 대표 pixel graphic 자리이고 그래픽은 넣지 않습니다. |
| Loading | 버튼을 누른 뒤 브라우저가 로그인 라우트로 이동하기 전 | `StatusScreen` kind `loading`, code `Authenticating`, label "Connecting to GitHub...". 디자인의 `AuthDots`는 만들지 않았습니다. |
| Error | `authError`가 아래 표의 키 | `StatusScreen` kind `error`, code `ERROR / AUTH`, label "Unable to connect to GitHub.", sub는 종류별 문구, action `Try again`. |

인증 중 플래그는 `src/components/shell/auth-transition.tsx`의 `AuthTransitionProvider`가 들고 있고 `layout.tsx`가 헤더와 화면을 함께 감쌉니다. 헤더의 `Log in with GitHub`와 화면의 `Continue with GitHub`는 같은 `LoginLink`라 어느 쪽으로 시작해도 이 화면이 AUTHENTICATING을 그리고 헤더 링크는 `Connecting to GitHub…`에 `aria-busy`가 붙습니다. 인증 중 판정은 오류 판정보다 앞입니다. `useAuthTransition()`은 provider 밖에서 부르면 예외를 던집니다. PR #100 리뷰 1차가 이 지점이었고 경위는 `raw/2026-09-11-GitHub-로그인-진입-화면-리뷰-1차-session-log.md`에 있습니다.

Loading 전환 규칙은 셋입니다. 이동은 `<a href>`에 맡기고 onClick은 공용 플래그만 세웁니다. 수정키나 가운데 버튼 클릭은 새 탭으로 열려 이 화면이 남으므로 플래그를 세우지 않습니다. bfcache에서 복원되면 `pageshow`의 `persisted`로 플래그를 되돌립니다.

`Try again`은 `router.replace("/")`로 쿼리를 지워 로그인 화면으로 돌아갑니다. 디자인과 같은 동작입니다.

## 3. 오류 종류별 안내

`AUTH_ERROR_COPY`는 `login-screen.tsx`에 있고 `Object.hasOwn`으로 조회합니다. 표에 없는 값과 프로토타입 키는 안내로 취급하지 않고 기본 화면을 그립니다. 종류는 콜백 라우트와 로그인 라우트가 정하며 바꾸지 않았습니다.

| 종류 | sub 문구 | 이전 한국어 문구 |
| --- | --- | --- |
| `access_denied` | You cancelled the GitHub authorization. You can log in again. | GitHub에서 권한 허용을 취소했습니다. 다시 로그인할 수 있습니다. |
| `state_mismatch` | We couldn't verify the login request. Start the login again from the beginning. | 로그인 요청을 확인하지 못했습니다. 처음부터 다시 로그인해야 합니다. |
| `exchange_failed` | GitHub authentication didn't complete. Try again in a moment. | GitHub 인증을 마치지 못했습니다. 잠시 후 다시 시도해 주세요. |
| `config_missing` | The server has no GitHub login configuration. A server administrator needs to complete the setup. | 서버에 GitHub 로그인 설정이 없습니다. 서버 관리자가 설정을 완료해야 합니다. |

## 4. 경로 상수

`src/lib/github/auth-paths.ts`가 `LOGIN_PATH`와 `SESSION_PATH`를 export합니다. `top-header.tsx`, `account-menu.tsx`, `login-screen.tsx`, `repository-analysis-view.tsx`가 모두 여기서 가져옵니다. 이전에는 헤더와 뷰가 각각 상수를 들고 있었습니다.

## 5. 테스트

- `src/features/auth/login-screen.test.tsx`: 기본 화면, 두 진입점의 AUTHENTICATING 전환, ERROR / AUTH 위에서의 헤더 진입, 수정키 클릭 4종, bfcache 복원 3종, `auth_error` 4종, Try again, 프로토타입 키 4종.
- `src/components/shell/top-header.test.tsx`: 헤더 로그인의 인증 중 표시와 수정키 클릭 4종. `src/components/shell/auth-transition.test.tsx`: provider 밖 예외.
- `src/app/page.test.tsx`: `next/headers`의 `cookies`를 mock해 서버 컴포넌트를 직접 렌더합니다. 세션 유무 분기, `auth_error` 첫 값 적용, 세션이 있을 때 `auth_error` 무시, 서버가 세션 없이 다시 그릴 때의 전환.
- `repository-analysis-view.test.tsx`의 로그인 관련 테스트는 위 두 파일로 옮겼고, 남은 로그아웃 테스트는 폼과 결과가 사라지는지를 확인합니다.

## 6. 확인한 것

- 테스트 958개, lint, typecheck 통과.
- dev 서버 curl 여섯 상태와 Playwright 클릭 흐름. 클릭 2밀리초 뒤 이전 문서에 AUTHENTICATING이 그려지고 `pagehide`까지 유지됩니다. 이동 중 DOM은 Playwright `evaluate`나 CDP로 읽으면 새 문서를 겨냥하므로 클릭 전에 심은 `MutationObserver` 기록으로 확인해야 합니다.

## 7. 확인 필요

- bfcache 복원 시 플래그 되돌림은 jsdom 테스트로만 확인했습니다. 실제 브라우저의 뒤로 가기는 GitHub 인증 페이지가 있어야 밟을 수 있습니다.
- `RepositoryAnalysisView`가 `hasSession={false}`를 받는 경로는 `page.tsx`에는 없습니다. 서버가 다시 그리면 화면 자체가 `LoginScreen`으로 바뀌기 때문입니다. 세션 없는 prop을 처리하는 코드와 테스트는 다른 부모가 이 화면을 그릴 때를 위해 남겨 두었고, 필요 없다고 판단되면 후속에서 정리합니다.
- 노션 기능 정의서에 한국어 로그인 안내 문구가 있는지 확인하지 않았습니다.
