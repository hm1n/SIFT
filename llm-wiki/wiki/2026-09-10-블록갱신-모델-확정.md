# 블록 갱신 모델 확정

> 2026-09-11 개정: 이 문서의 출력 계약(블록 전체 재작성, 문장별 인용 배열)과 입력 계약(현재 블록과 직전 질문·답변)은 `wiki/2026-09-11-PAAR-경험블록-설계-개정.md`가 대체합니다. 모델 `gpt-5.6-luna`, 변형 `merged`, 명시 캐시 경계, 직렬 구조, 비용 수치는 그대로 유효합니다. 새 계약의 실측은 개정 문서 12절의 확인 필요 항목입니다.

PAAR 경험 블록을 다시 쓰는 호출(이슈 #88)의 모델, 프롬프트 변형, 캐시 방식, 호출 구조를 한곳에 모읍니다. 후보 조사와 측정 경위는 위 두 세션 로그에 있고 이 문서는 결론만 담습니다.

## 확정

| 항목 | 값 | 코드 |
| --- | --- | --- |
| 모델 | `gpt-5.6-luna`, 추론 끔 | `BLOCK_UPDATE_MODEL`, `BLOCK_UPDATE_REASONING_EFFORT` |
| 프롬프트 변형 | `merged` | `BLOCK_UPDATE_PROMPT_VARIANT` |
| 프롬프트 캐시 | 명시 모드, 근거 블록 끝에 경계 | 서버 경로(하위 이슈 B)에서 배선 |
| 호출 구조 | 블록 갱신 뒤 다음 질문, 직렬 유지 | |
| 출력 상한 | 900토큰 (이력 항목 상한 4,500바이트 ÷ 5) | `BLOCK_MAX_OUTPUT_TOKENS` |

## 1. 후보

2026-09-10에 Anthropic, OpenAI, xAI, DeepSeek, Mistral, Google, Alibaba, Amazon의 소형·중형 모델 21개를 요금과 캐시 단가로 정리했습니다. 표는 `raw/2026-09-10-블록갱신-모델-후보-리스트업-session-log.md` 3절에 있습니다. 실측은 현행 모델 `gemini-3.1-flash-lite`와 저가 캐시형 최신 세대 `gpt-5.6-luna` 둘로 좁혔습니다. 나머지는 실측하지 않았습니다.

## 2. 판정 기준과 결과

같은 근거(공개 PR #61), 같은 합성 답변 10개, 변형 2개로 모델당 20건을 비교했습니다.

| 기준 | gemini-3.1-flash-lite | gpt-5.6-luna |
| --- | --- | --- |
| 창작 | 주입 문장을 repository 출처로 씀, patch 없는 파일의 구현을 설명, 근거 없는 인과 문장 | 40건에서 근거 없는 사실 없음 |
| sufficient 판정 | 거절·철회·주입 픽스처에서도 true (19/20) | `merged`는 그 픽스처 모두 false |
| 답변 제출부터 다음 질문 첫 조각 | 중앙 약 3.0초, 최대 3.5초 | 중앙 2.6~3.3초, 최대 5.5초 |
| 회당 비용 | 0.0020달러, 암묵 캐시 1/20 | 명시 캐시로 0.0003달러 (첫 턴 0.0014) |
| 출력 최대 | 631토큰 | 383토큰 |

지연은 판정선 20초 안에서 갈리지 않았으므로 창작 비율과 비용으로 골랐습니다.

## 3. 캐시 규칙

OpenAI 암묵 모드는 마지막 메시지 끝에 경계를 두어 턴마다 바뀌는 답변까지 전체가 같아야 히트합니다. 1차 실측에서 그 때문에 매 호출 입력 전량이 캐시 쓰기(1.25배)로 과금되고 읽기가 0이었습니다. `prompt_cache_options.mode = "explicit"`로 바꾸고 근거 `input_text` 블록에 `prompt_cache_breakpoint`를 붙이면 20건 중 18건이 히트합니다. 시스템 프롬프트는 최상위 `instructions`가 아니라 developer 메시지의 `input_text` 블록에 실어야 경계 앞에 들어갑니다.

## 4. 인터뷰 회당 비용 변화

이 호출이 매 턴 하나씩 붙습니다. 10턴 기준입니다.

| 항목 | 값 |
| --- | --- |
| 블록 갱신 10턴 | 약 0.004달러 |
| 인터뷰 완주 10턴 (짧은 답변) | 0.03405달러 → 약 0.038달러 |
| 10달러 가능 횟수 | 293회 → 약 263회 |

Gemini를 그대로 썼다면 약 0.054달러, 185회였습니다. 갱신된 값은 `wiki/2026-09-02-LLM-비용-산정.md` 3절과 4절에 반영했습니다.

## 5. 하지 않기로 한 것

- 다른 후보를 실측하지 않았습니다. 두 모델 비교로 판정이 갈렸습니다.
- 지연 대안 둘(같은 블록 질문을 먼저 만드는 방법, 질문 호출에서 블록 갱신을 함께 받는 방법)은 검토하지 않았습니다. 지연이 판정선 안입니다.
- Gemini 암묵 캐싱이 낮게 걸린 원인은 확인하지 않았습니다. 탈락한 모델입니다.

## 6. 확인 필요

- 서버 경로에서 `@ai-sdk/openai`가 Responses API의 `prompt_cache_options`와 `prompt_cache_breakpoint`를 어떻게 노출하는지 확인해야 합니다. 노출하지 않으면 provider option 또는 직접 호출로 배선합니다.
- 창작 비율 판독은 AI가 1차로 하고 사용자가 확정했습니다. 운영 답변으로 다시 셀 기회가 오면 갱신합니다.
- gpt-5.6-luna는 `OPENAI_API_KEY` 운영 설정이 필요합니다. 프로덕션 설정은 하위 이슈 B에서 합니다.
